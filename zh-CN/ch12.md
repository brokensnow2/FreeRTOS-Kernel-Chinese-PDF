<a id="122-configassert"></a>
## 12.2 configASSERT()

在 C 语言中，`assert()` 宏用于验证程序作出的*断言*，也就是某项假设。断言以 C 表达式编写；如果表达式求值为假（0），就认为断言失败。例如，代码清单 12.1 验证指针 `pxMyPointer` 不为 NULL。

<a name="list12.1" title="代码清单 12.1 使用标准 C assert() 宏检查 pxMyPointer 不为 NULL"></a>

```c
/* 验证 pxMyPointer 不为 NULL。 */
assert( pxMyPointer != NULL );
```

***代码清单 12.1*** *使用标准 C `assert()` 宏检查 `pxMyPointer` 不为 NULL*

应用程序开发者通过实现 `assert()` 宏，指定断言失败时要执行的操作。

FreeRTOS 源代码不调用 `assert()`，因为并非所有用于编译 FreeRTOS 的编译器都提供 `assert()`。FreeRTOS 源代码改为大量调用 `configASSERT()` 宏。应用程序开发者可以在 FreeRTOSConfig.h 中定义该宏，其行为与标准 C `assert()` 完全相同。

断言失败必须被视为致命错误。不要尝试继续执行已经发生断言失败的代码行之后的代码。

> *使用 `configASSERT()` 可以立即捕获并定位许多最常见的错误来源，从而提高开发效率。强烈建议在开发或调试 FreeRTOS 应用程序时定义 `configASSERT()`。*

定义 `configASSERT()` 对运行时调试很有帮助，但也会增大应用程序代码体积，并降低执行速度。如果没有提供 `configASSERT()` 的定义，系统会使用默认的空定义，C 预处理器会完全移除对 `configASSERT()` 的所有调用。

<a id="1221-example-configassert-definitions"></a>
### 12.2.1 configASSERT() 定义示例

在调试器控制下运行应用程序时，可以使用代码清单 12.2 所示的 `configASSERT()` 定义。任何代码行发生断言失败时，该定义都会停止执行，因此暂停调试会话后，调试器显示的正是断言失败的代码行。

<a name="list12.2" title="代码清单 12.2 在调试器控制下运行时适用的简单 configASSERT() 定义"></a>

```c
/* 禁用中断以停止执行 Tick 中断，然后停留在循环中，避免继续执行断言失败
   代码行之后的代码。如果硬件支持调试断点指令，可以用调试断点指令替代
   for() 循环。 */

#define configASSERT( x ) if( ( x ) == 0 ) { taskDISABLE_INTERRUPTS(); for(;;); }
```

***代码清单 12.2*** *在调试器控制下运行时适用的简单 `configASSERT()` 定义*

应用程序不在调试器控制下运行时，可以使用代码清单 12.3 所示的 `configASSERT()` 定义。该定义会输出或以其他方式记录断言失败的源代码行。它使用标准 C `__FILE__` 宏获取源文件名，并使用标准 C `__LINE__` 宏获取源文件中的行号，以确定断言失败的位置。

<a name="list12.3" title="代码清单 12.3 记录断言失败源代码行的 configASSERT() 定义"></a>

```c
/* 必须在 C 源文件中定义此函数，而不能在 FreeRTOSConfig.h 头文件中定义。 */
void vAssertCalled( const char *pcFile, uint32_t ulLine )
{
    /* 在此函数中，pcFile 保存包含错误检测代码行的源文件名，ulLine 保存该代码行
       在源文件中的行号。进入下面的无限循环之前，可以输出或以其他方式记录
       pcFile 和 ulLine 的值。 */
    RecordErrorInformationHere( pcFile, ulLine );

    /* 禁用中断以停止执行 Tick 中断，然后停留在循环中，避免继续执行断言失败
       代码行之后的代码。 */
    taskDISABLE_INTERRUPTS();
    for( ;; );
}
/*-----------------------------------------------------------*/

/* 以下两行必须放在 FreeRTOSConfig.h 中。 */
extern void vAssertCalled( const char *pcFile, unsigned long ulLine );
#define configASSERT( x ) if( ( x ) == 0 ) vAssertCalled( __FILE__, __LINE__ )
```

<a id="125-viewing-run-time-and-task-state-information"></a>
## 12.5 查看运行时间与任务状态信息

<a id="1251-task-run-time-statistics"></a>
### 12.5.1 任务运行时间统计

任务运行时间统计提供每个任务获得的处理器时间信息。任务的*运行时间*是应用程序启动以来，该任务处于运行状态的总时间。

运行时间统计旨在项目开发阶段辅助性能分析和调试。它提供的信息仅在作为运行时间统计时钟的计数器溢出之前有效。收集运行时间统计会增加任务上下文切换所需的时间。

要获得二进制形式的运行时间统计信息，请调用 `uxTaskGetSystemState()` API 函数。要获得人类可读 ASCII 表格形式的运行时间统计信息，请调用 `vTaskGetRunTimeStatistics()` 辅助函数。

<a id="1252-the-run-time-statistics-clock"></a>
### 12.5.2 运行时间统计时钟

运行时间统计需要测量小于一个 Tick 周期的时间。因此，系统不使用 RTOS Tick 计数作为运行时间统计时钟，而是由应用程序代码提供该时钟。建议让运行时间统计时钟的频率达到 Tick 中断频率的 10 到 100 倍。运行时间统计时钟越快，统计结果越准确，但时间值也越早溢出。

理想情况下，时间值应由一个自由运行的 32 位外设定时器或计数器生成，并且读取该值不需要额外处理开销。如果可用外设和时钟速度无法实现这种方案，也可以使用以下效率较低的方法：

- 配置一个外设，使其以所需的运行时间统计时钟频率产生周期性中断，然后把已产生的中断次数用作运行时间统计时钟。

  如果周期性中断仅用于提供运行时间统计时钟，这种方法效率很低。不过，如果应用程序已经使用频率合适的周期性中断，那么只需在现有中断服务程序中增加一个中断次数计数，就能简单而高效地实现。

- 使用自由运行的 16 位外设定时器的当前值作为 32 位值的低 16 位，并使用定时器溢出次数作为 32 位值的高 16 位，从而生成一个 32 位值。

通过适当但较复杂的处理，也可以把 RTOS Tick 计数与 ARM Cortex-M SysTick 定时器的当前值组合起来，生成运行时间统计时钟。FreeRTOS 下载包中的一些演示项目展示了这种实现方式。

<a id="1253-configuring-an-application-to-collect-run-time-statistics"></a>
### 12.5.3 配置应用程序以收集运行时间统计

下面介绍收集任务运行时间统计所需的宏。这些宏最初准备放在 RTOS 移植层中，因此名称带有“port”前缀，但实践证明在 FreeRTOSConfig.h 中定义它们更合适。

**用于收集运行时间统计的宏**

- `configGENERATE_RUN_TIME_STATS`

  必须在 FreeRTOSConfig.h 中把该宏设为 1。设为 1 后，调度器会在适当时机调用本节介绍的其他宏。

- `portCONFIGURE_TIMER_FOR_RUN_TIME_STATS()`

  必须提供该宏，用于初始化提供运行时间统计时钟的外设。

- `portGET_RUN_TIME_COUNTER_VALUE()` 或 `portALT_GET_RUN_TIME_COUNTER_VALUE(Time)`

  必须提供这两个宏中的一个，用于返回当前运行时间统计时钟值。该值以运行时间统计时钟为单位，表示应用程序自首次启动以来的总运行时间。

  使用第一个宏时，必须把它定义为求值结果等于当前时钟值的表达式。使用第二个宏时，必须把它定义为将其 `Time` 参数设置为当前时钟值。

<a id="1254-the-uxtaskgetsystemstate-api-function"></a>
### 12.5.4 uxTaskGetSystemState() API 函数

`uxTaskGetSystemState()` 提供由 FreeRTOS 调度器管理的每个任务的状态信息快照。信息以 `TaskStatus_t` 结构体数组的形式提供，数组中的每个索引对应一个任务。代码清单 12.5 和后文介绍了 `TaskStatus_t`。

<a name="list12.4" title="代码清单 12.4 uxTaskGetSystemState() API 函数原型"></a>

```c
UBaseType_t uxTaskGetSystemState( TaskStatus_t * const pxTaskStatusArray,
                                  const UBaseType_t uxArraySize,
                                  configRUN_TIME_COUNTER_TYPE * const pulTotalRunTime );
```

***代码清单 12.4*** *`uxTaskGetSystemState()` API 函数原型*

> 注意：为了向后兼容，`configRUN_TIME_COUNTER_TYPE` 默认为 `uint32_t`；如果 `uint32_t` 的范围不足，可以在 FreeRTOSConfig.h 中覆盖该类型。

**uxTaskGetSystemState() 参数和返回值**

- `pxTaskStatusArray`

  指向 `TaskStatus_t` 结构体数组的指针。

  数组必须为每个任务至少包含一个 `TaskStatus_t` 结构体。可以使用 `uxTaskGetNumberOfTasks()` API 函数确定任务数量。

  代码清单 12.5 给出了 `TaskStatus_t` 结构体，下一组列表介绍其成员。

- `uxArraySize`

  `pxTaskStatusArray` 参数所指数组的大小。大小以数组索引数，也就是数组中包含的 `TaskStatus_t` 结构体数量表示，而不是以数组的字节数表示。

- `pulTotalRunTime`

  如果在 FreeRTOSConfig.h 中把 `configGENERATE_RUN_TIME_STATS` 设为 1，`uxTaskGetSystemState()` 会把目标系统启动以来的总运行时间写入 `*pulTotalRunTime`。该时间由应用程序提供的运行时间统计时钟定义。

  `pulTotalRunTime` 是可选参数；如果不需要总运行时间，可以将其设为 NULL。

- 返回值

  返回 `uxTaskGetSystemState()` 实际填充的 `TaskStatus_t` 结构体数量。

  返回值应当等于 `uxTaskGetNumberOfTasks()` API 函数的返回值；如果 `uxArraySize` 参数传入的值太小，则返回 0。

<a name="list12.5" title="代码清单 12.5 TaskStatus_t 结构体"></a>

```c
typedef struct xTASK_STATUS
{
    TaskHandle_t xHandle;
    const char *pcTaskName;
    UBaseType_t xTaskNumber;
    eTaskState eCurrentState;
    UBaseType_t uxCurrentPriority;
    UBaseType_t uxBasePriority;
    configRUN_TIME_COUNTER_TYPE ulRunTimeCounter;
    StackType_t * pxStackBase;
    #if ( ( portSTACK_GROWTH > 0 ) || ( configRECORD_STACK_HIGH_ADDRESS == 1 ) )
        StackType_t * pxTopOfStack;
        StackType_t * pxEndOfStack;
    #endif
    uint16_t usStackHighWaterMark;
    #if ( ( configUSE_CORE_AFFINITY == 1 ) && ( configNUMBER_OF_CORES > 1 ) )
        UBaseType_t uxCoreAffinityMask;
    #endif
} TaskStatus_t;
```

***代码清单 12.5*** *`TaskStatus_t` 结构体*

**TaskStatus_t 结构体成员**

- `xHandle`

  该结构体中的信息所对应任务的句柄。

- `pcTaskName`

  人类可读的任务文本名称。

- `xTaskNumber`

  每个任务都有唯一的 `xTaskNumber` 值。

  如果应用程序在运行时创建和删除任务，新任务可能获得与之前已删除任务相同的句柄。`xTaskNumber` 使应用程序代码和支持内核感知的调试器能够区分仍然有效的任务，以及曾经具有相同句柄但已经删除的任务。

- `eCurrentState`

  保存任务状态的枚举类型。`eCurrentState` 可以是以下值之一：

  - `eRunning`
  - `eReady`
  - `eBlocked`
  - `eSuspended`
  - `eDeleted`

  只有从调用 `vTaskDelete()` 删除任务开始，到空闲任务释放为已删除任务的内部数据结构和栈分配的内存为止，这一小段时间内才会报告任务处于 `eDeleted` 状态。此后该任务将彻底不存在，尝试使用其句柄属于无效操作。

- `uxCurrentPriority`

  调用 `uxTaskGetSystemState()` 时任务运行所采用的优先级。只有任务依据[第 8.3 节“互斥量（与二值信号量）”](ch08.md#83-mutexes-and-binary-semaphores)介绍的优先级继承机制，临时获得更高优先级时，`uxCurrentPriority` 才会高于应用程序开发者为任务分配的优先级。

- `uxBasePriority`

  应用程序开发者分配给任务的优先级。只有在 FreeRTOSConfig.h 中把 `configUSE_MUTEXES` 设为 1 时，`uxBasePriority` 才有效。

- `ulRunTimeCounter`

  任务自创建以来使用的总运行时间。总运行时间以绝对时间值提供，并使用应用程序开发者为收集运行时间统计而提供的时钟。只有在 FreeRTOSConfig.h 中把 `configGENERATE_RUN_TIME_STATS` 设为 1 时，`ulRunTimeCounter` 才有效。

- `pxStackBase`

  指向分配给该任务的栈区域基地址。

- `pxTopOfStack`

  指向分配给该任务的栈区域当前栈顶地址。只有栈向上增长，也就是 `portSTACK_GROWTH` 大于 0，或者在 FreeRTOSConfig.h 中把 `configRECORD_STACK_HIGH_ADDRESS` 设为 1 时，`pxTopOfStack` 字段才有效。

- `pxEndOfStack`

  指向分配给该任务的栈区域末端地址。只有栈向上增长，也就是 `portSTACK_GROWTH` 大于 0，或者在 FreeRTOSConfig.h 中把 `configRECORD_STACK_HIGH_ADDRESS` 设为 1 时，`pxEndOfStack` 字段才有效。

- `usStackHighWaterMark`

  任务的栈高水位标记，也就是任务创建以来曾经剩余的最小栈空间。它反映任务离栈溢出有多近：该值越接近 0，任务就越接近栈溢出。`usStackHighWaterMark` 以字节为单位。

- `uxCoreAffinityMask`

  表示任务可以在哪些核心上运行的位掩码。核心编号从 0 到 `configNUMBER_OF_CORES - 1`。例如，可以在核心 0 和核心 1 上运行的任务，其 `uxCoreAffinityMask` 会设为 0x03。只有在 FreeRTOSConfig.h 中把 `configUSE_CORE_AFFINITY` 设为 1，并且把 `configNUMBER_OF_CORES` 设为大于 1 的值时，`uxCoreAffinityMask` 字段才可用。

<a id="1255-the-vtasklisttasks-helper-function"></a>
### 12.5.5 vTaskListTasks() 辅助函数

`vTaskListTasks()` 提供与 `uxTaskGetSystemState()` 类似的任务状态信息，但它把信息表示为人类可读的 ASCII 表格，而不是二进制值数组。

`vTaskListTasks()` 会占用大量处理器时间，并使调度器长时间保持挂起状态。因此，建议只将该函数用于调试，不要在生产环境的实时系统中使用。

如果在 FreeRTOSConfig.h 中把 `configUSE_TRACE_FACILITY` 设为 1，并把 `configUSE_STATS_FORMATTING_FUNCTIONS` 设为大于 0 的值，就可以使用 `vTaskListTasks()`。

<a name="list12.6" title="代码清单 12.6 vTaskListTasks() API 函数原型"></a>

```c
void vTaskListTasks( char * pcWriteBuffer, size_t uxBufferLength );
```

***代码清单 12.6*** *`vTaskListTasks()` API 函数原型*

**vTaskListTasks() 参数**

- `pcWriteBuffer`

  指向字符缓冲区的指针，函数会把格式化后的人类可读表格写入该缓冲区。假定该缓冲区足以容纳生成的报告。每个任务预留大约 40 字节通常已经足够。

- `uxBufferLength`

  `pcWriteBuffer` 的长度。

图 12.7 展示了 `vTaskListTasks()` 生成的输出。其中：

- 每一行提供一个任务的信息。

- 第一列是任务名称。

- 第二列是任务状态：“X”表示运行，“R”表示就绪，“B”表示阻塞，“S”表示挂起，“D”表示任务已删除。只有从调用 `vTaskDelete()` 删除任务开始，到空闲任务释放为已删除任务的内部数据结构和栈分配的内存为止，这一小段时间内才会报告任务处于已删除状态。此后该任务将彻底不存在，尝试使用其句柄属于无效操作。

- 第三列是任务优先级。

- 第四列是任务的栈高水位标记。请参见 `usStackHighWaterMark` 的说明。

- 第五列是分配给任务的唯一编号。请参见 `xTaskNumber` 的说明。

### 12.5.6 vTaskGetRunTimeStatistics() 辅助函数

`vTaskGetRunTimeStatistics()` 把收集到的运行时间统计格式化为人类可读的 ASCII 表格。

`vTaskGetRunTimeStatistics()` 会占用大量处理器时间，并使调度器长时间保持挂起状态。因此，建议只将该函数用于调试，不要在生产环境的实时系统中使用。

当 FreeRTOSConfig.h 中的 `configGENERATE_RUN_TIME_STATS` 设为 1、`configUSE_STATS_FORMATTING_FUNCTIONS` 设为大于 0 的值，并且 `configUSE_TRACE_FACILITY` 设为 1 时，可以使用 `vTaskGetRunTimeStatistics()`。

### 12.5.7 生成并显示运行时间统计：完整示例

本示例使用一个假想的 16 位定时器生成 32 位运行时间统计时钟。计数器配置为每当 16 位值达到最大值时产生一次中断，实际上也就是产生溢出中断。中断服务程序负责统计溢出次数。

以溢出次数作为 32 位值的最高两个字节，以当前 16 位计数器值作为 32 位值的最低两个字节，即可构成 32 位值。代码清单 12.10 给出了中断服务程序的伪代码。

<a name="list12.10" title="代码清单 12.10 用于统计定时器溢出次数的 16 位定时器溢出中断处理程序"></a>

```c
void TimerOverflowInterruptHandler( void )
{
    /* 只统计中断次数。 */
    ulOverflowCount++;

    /* 清除中断。 */
    ClearTimerInterrupt();
}
```

***代码清单 12.10*** *用于统计定时器溢出次数的 16 位定时器溢出中断处理程序*

代码清单 12.11 给出了为启用运行时间统计收集而添加到 FreeRTOSConfig.h 中的代码。

<a name="list12.11" title="代码清单 12.11 为启用运行时间统计收集而添加到 FreeRTOSConfig.h 的宏"></a>

```c
/* 将 configGENERATE_RUN_TIME_STATS 设为 1 以启用运行时间统计收集。
   完成此设置后，还必须定义 portCONFIGURE_TIMER_FOR_RUN_TIME_STATS()，
   以及 portGET_RUN_TIME_COUNTER_VALUE() 或
   portALT_GET_RUN_TIME_COUNTER_VALUE(x)。 */
#define configGENERATE_RUN_TIME_STATS 1

/* 把 portCONFIGURE_TIMER_FOR_RUN_TIME_STATS() 定义为调用
   用于配置假想 16 位定时器的函数
   （未给出该函数的实现）。 */
void vSetupTimerForRunTimeStats( void );
#define portCONFIGURE_TIMER_FOR_RUN_TIME_STATS()  vSetupTimerForRunTimeStats()

/* 把 portALT_GET_RUN_TIME_COUNTER_VALUE() 定义为将其参数设置为
   当前运行时间计数器或时间值。返回的时间值为 32 位，
   先把 16 位定时器的溢出次数左移到
   32 位数的最高两个字节，再将结果与
   当前 16 位计数器值执行按位 OR。 */
#define portALT_GET_RUN_TIME_COUNTER_VALUE( ulCountValue )                  \
{                                                                           \
    extern volatile unsigned long ulOverflowCount;                          \
                                                                            \
    /* 断开计数器的时钟，使其数值在                                             \
       使用期间保持不变。               */                                    \
    PauseTimer();                                                           \
                                                                            \
    /* 把溢出次数移入返回的 32 位值的                                          \
       最高两个字节。                            */                           \
    ulCountValue = ( ulOverflowCount << 16UL );                             \
                                                                            \
    /* 把当前计数器值用作返回的 32 位值的                                       \
       最低两个字节。                        */                               \
    ulCountValue |= ( unsigned long ) ReadTimerCount();                     \
                                                                            \
    /* 重新连接计数器的时钟。                 */                               \
    ResumeTimer();                                                          \
}
```

***代码清单 12.11*** *为启用运行时间统计收集而添加到 FreeRTOSConfig.h 的宏*

代码清单 12.12 所示的任务每 5 秒输出一次收集到的运行时间统计。

<a name="list12.12" title="代码清单 12.12 输出所收集运行时间统计的任务"></a>

```c
#define RUN_TIME_STATS_STRING_BUFFER_LENGTH       512

/* 为了清晰起见，本代码清单省略了对 fflush() 的调用。 */
static void prvStatsTask( void *pvParameters )
{
    TickType_t xLastExecutionTime;

    /* 用于保存格式化运行时间统计文本的缓冲区需要相当大。
       因此把它声明为 static，确保它不会
       分配到任务栈上。这也使该函数不可重入。 */
    static signed char cStringBuffer[ RUN_TIME_STATS_STRING_BUFFER_LENGTH ];

    /* 该任务每 5 秒运行一次。 */
    const TickType_t xBlockPeriod = pdMS_TO_TICKS( 5000 );

    /* 将 xLastExecutionTime 初始化为当前时间。这是唯一
       需要显式写入该变量的时刻，之后由
       vTaskDelayUntil() API 函数在内部更新它。 */
    xLastExecutionTime = xTaskGetTickCount();

    /* 与大多数任务一样，该任务通过无限循环实现。 */
    for( ;; )
    {
        /* 等待下一次运行该任务的时刻。 */
        xTaskDelayUntil( &xLastExecutionTime, xBlockPeriod );

        /* 根据运行时间统计生成文本表格。该表格必须能装入
           cStringBuffer 数组。 */
        vTaskGetRunTimeStatistics( cStringBuffer, RUN_TIME_STATS_STRING_BUFFER_LENGTH );

        /* 输出运行时间统计表的列标题。 */
        printf( "\nTask\t\tAbs\t\t\t%%\n" );
        printf( "-------------------------------------------------------------\n" );

        /* 输出运行时间统计本身。数据表包含
           多行，因此调用 vPrintMultipleLines()，
           而不是直接调用 printf()。vPrintMultipleLines()
           只是分别对每一行调用 printf()，
           以确保行缓冲按预期工作。 */ 
        vPrintMultipleLines( cStringBuffer );
    }
}
```

<a id="126-trace-hook-macros"></a>
## 12.6 跟踪钩子宏

跟踪宏是放置在 FreeRTOS 源代码关键位置的宏。默认情况下，这些宏为空，不生成任何代码，也不会产生运行时开销。应用程序开发者可以覆盖默认的空实现，从而：

- 在不修改 FreeRTOS 源文件的情况下，把代码插入 FreeRTOS。

- 通过目标硬件提供的任意方式输出详细的执行顺序信息。FreeRTOS 源代码中的跟踪宏分布足够广泛，可以用它们创建完整、详细的调度器活动跟踪和性能分析日志。

<a id="1261-available-trace-hook-macros"></a>
### 12.6.1 可用的跟踪钩子宏

逐一详述所有宏会占用过多篇幅。下面列出应用程序开发者最常用的一部分宏。

下列许多说明都引用名为 `pxCurrentTCB` 的变量。`pxCurrentTCB` 是 FreeRTOS 的私有变量，用于保存处于运行状态的任务句柄；从 FreeRTOS/Source/tasks.c 源文件调用的任何宏都可以访问它。

**常用跟踪钩子宏选集**

- `traceTASK_INCREMENT_TICK(xTickCount)`

  在 Tick 中断期间、Tick 计数递增之前调用。`xTickCount` 参数把新的 Tick 计数值传入宏。

- `traceTASK_SWITCHED_OUT()`

  在选择新任务运行之前调用。此时，`pxCurrentTCB` 保存即将离开运行状态的任务句柄。

- `traceTASK_SWITCHED_IN()`

  在选定一个任务运行之后调用。此时，`pxCurrentTCB` 保存即将进入运行状态的任务句柄。

- `traceBLOCKING_ON_QUEUE_RECEIVE(pxQueue)`

  当前执行的任务尝试从空队列读取数据，或者尝试“获取”空信号量或互斥量，因而即将进入阻塞状态时调用。`pxQueue` 参数把目标队列或信号量的句柄传入宏。

- `traceBLOCKING_ON_QUEUE_SEND(pxQueue)`

  当前执行的任务尝试向已满队列写入数据，因而即将进入阻塞状态时调用。`pxQueue` 参数把目标队列的句柄传入宏。

- `traceQUEUE_SEND(pxQueue)`

  在 `xQueueSend()`、`xQueueSendToFront()`、`xQueueSendToBack()` 或任意信号量“释放”函数内部，当队列发送或信号量释放成功时调用。`pxQueue` 参数把目标队列或信号量的句柄传入宏。

- `traceQUEUE_SEND_FAILED(pxQueue)`

  在 `xQueueSend()`、`xQueueSendToFront()`、`xQueueSendToBack()` 或任意信号量“释放”函数内部，当队列发送或信号量释放失败时调用。如果队列已满，并且在指定的整个阻塞时间内始终保持已满，队列发送或信号量释放就会失败。`pxQueue` 参数把目标队列或信号量的句柄传入宏。

- `traceQUEUE_RECEIVE(pxQueue)`

  在 `xQueueReceive()` 或任意信号量“获取”函数内部，当队列接收或信号量获取成功时调用。`pxQueue` 参数把目标队列或信号量的句柄传入宏。

- `traceQUEUE_RECEIVE_FAILED(pxQueue)`

  在 `xQueueReceive()` 或任意信号量“获取”函数内部，当队列或信号量接收操作失败时调用。如果队列或信号量为空，并且在指定的整个阻塞时间内始终保持为空，队列接收或信号量获取就会失败。`pxQueue` 参数把目标队列或信号量的句柄传入宏。

- `traceQUEUE_SEND_FROM_ISR(pxQueue)`

  在 `xQueueSendFromISR()` 内部，当发送操作成功时调用。`pxQueue` 参数把目标队列的句柄传入宏。

- `traceQUEUE_SEND_FROM_ISR_FAILED(pxQueue)`

  在 `xQueueSendFromISR()` 内部，当发送操作失败时调用。如果队列已经满，发送操作就会失败。`pxQueue` 参数把目标队列的句柄传入宏。

- `traceQUEUE_RECEIVE_FROM_ISR(pxQueue)`

  在 `xQueueReceiveFromISR()` 内部，当接收操作成功时调用。`pxQueue` 参数把目标队列的句柄传入宏。

- `traceQUEUE_RECEIVE_FROM_ISR_FAILED(pxQueue)`

  在 `xQueueReceiveFromISR()` 内部，当队列已经为空而导致接收操作失败时调用。`pxQueue` 参数把目标队列的句柄传入宏。

- `traceTASK_DELAY_UNTIL( xTimeToWake )`

  在 `xTaskDelayUntil()` 内部，紧接在调用任务进入阻塞状态之前调用。

- `traceTASK_DELAY()`

  在 `vTaskDelay()` 内部，紧接在调用任务进入阻塞状态之前调用。

<a id="1262-defining-trace-hook-macros"></a>
### 12.6.2 定义跟踪钩子宏

每个跟踪宏都有默认的空定义。可以在 FreeRTOSConfig.h 中提供新的宏定义，以覆盖默认定义。如果跟踪宏定义变得很长或很复杂，可以在新的头文件中实现它们，再从 FreeRTOSConfig.h 包含该头文件。

按照软件工程最佳实践，FreeRTOS 实施严格的数据隐藏策略。跟踪宏允许把用户代码加入 FreeRTOS 源文件，因此跟踪宏可见的数据类型与应用程序代码可见的数据类型不同：

- 在 FreeRTOS/Source/tasks.c 源文件内部，任务句柄是指向任务描述数据结构，也就是任务*任务控制块*（Task Control Block，TCB）的指针。在 FreeRTOS/Source/tasks.c 源文件外部，任务句柄是 void 指针。

- 在 FreeRTOS/Source/queue.c 源文件内部，队列句柄是指向队列描述数据结构的指针。在 FreeRTOS/Source/queue.c 源文件外部，队列句柄是 void 指针。

> *如果跟踪宏直接访问通常属于私有的 FreeRTOS 数据结构，必须格外谨慎，因为私有数据结构可能在不同 FreeRTOS 版本之间发生变化。*
