# 2 FreeRTOS 内核发行版

<a id="21-introduction"></a>
## 2.1 引言

为帮助用户熟悉 FreeRTOS 内核文件和目录，本章：

<a id="22-understanding-the-freertos-distribution"></a>
## 2.2 理解 FreeRTOS 发行版

<a id="221-definition-freertos-port"></a>
### 2.2.1 定义：FreeRTOS 移植版

FreeRTOS 可以使用大约二十种不同的编译器构建，并可在超过四十种不同的处理器架构上运行。每种支持的编译器和处理器组合称为一个 FreeRTOS 移植版。

<a id="222-building-freertos"></a>
### 2.2.2 构建 FreeRTOS

FreeRTOS 是一个为原本单线程的裸机应用提供多任务能力的库。

FreeRTOS 以一组 C 源文件的形式提供。某些源文件是所有移植版通用的，而其他源文件则是特定移植版专用的。将这些源文件作为项目的一部分进行编译，可使 FreeRTOS API 对您的应用可用。为每个官方 FreeRTOS 移植版提供了一个可用作参考的演示应用。演示应用已预配置为编译正确的源文件并包含正确的头文件。

在创建时，每个演示应用都是"开箱即用"的，没有编译器错误或警告。如果后续构建工具的更改导致情况不再如此，请使用 FreeRTOS 支持论坛 (<https://forums.FreeRTOS.org>) 告知我们。第 2.3 节描述了演示应用。

<a id="223-freertosconfigh"></a>
### 2.2.3 FreeRTOSConfig.h

在名为 FreeRTOSConfig.h 的头文件中定义的常量用于配置内核。不要直接在源文件中包含 FreeRTOSConfig.h！而是包含 FreeRTOS.h，它会在适当时机包含 FreeRTOSConfig.h。

FreeRTOSConfig.h 用于为特定应用定制 FreeRTOS 内核。例如，FreeRTOSConfig.h 包含诸如 `configUSE_PREEMPTION` 之类的常量，该常量定义 FreeRTOS 使用协作式还是抢占式调度[^1]。

[^1]: 第 4.13 节描述了调度算法。

FreeRTOSConfig.h 为特定应用定制 FreeRTOS，因此应位于属于应用目录的一部分，而不是包含 FreeRTOS 源代码的目录。

主要的 FreeRTOS 发行版为每个 FreeRTOS 移植版包含一个演示应用，并且每个演示应用都有自己的 FreeRTOSConfig.h 文件。建议从您使用的 FreeRTOS 移植版所提供的演示应用使用的 FreeRTOSConfig.h 开始，然后进行调整，而不是从头创建该文件。

FreeRTOS 参考手册和 <https://www.freertos.org/a00110.html> 描述了出现在 FreeRTOSConfig.h 中的常量。不必包含 FreeRTOSConfig.h 中的所有常量——许多常量在省略时会获得默认值。

<a id="224-official-distributions"></a>
### 2.2.4 官方发行版

各个 FreeRTOS 库（包括内核）可从各自的 Github 仓库以及 zip 文件存档中获得。在生产代码中使用 FreeRTOS 时，能够获取单个库非常方便。然而，入门时最好下载主要的 FreeRTOS 发行版，因为它同时包含库和示例项目。

主要的发行版包含所有 FreeRTOS 库的源代码、所有 FreeRTOS 内核移植版以及所有 FreeRTOS 演示应用的项目文件。不要被文件数量吓到！应用只需要其中的一小部分。

使用 <https://github.com/FreeRTOS/FreeRTOS/releases/latest> 下载包含最新发行版的 zip 文件。或者，使用以下 Git 命令之一从 GitHub 克隆主发行版，其中包含从其各自的 Git 仓库子模块化的各个库：

git clone git@github.com:FreeRTOS/FreeRTOS.git --recurse-submodules

<a id="225-freertos-source-files-common-to-all-ports"></a>
### 2.2.5 所有移植版通用的 FreeRTOS 源文件

tasks.c 和 list.c 实现了核心 FreeRTOS 内核功能，始终是必需的。它们位于 FreeRTOS/Source 目录中，如图 2.2 所示。同一目录还包含以下可选的源文件：

- **queue.c**

   queue.c 提供队列和信号量服务，如本书后续所述。queue.c 几乎总是必需的。

- **timers.c**

   timers.c 提供软件定时器功能，如本书后续所述。仅当应用使用软件定时器时才需要构建。

- **event\_groups.c**

   event\_groups.c 提供事件组功能，如本书后续所述。仅当应用使用事件组时才需要构建。

- **stream\_buffer.c**

   stream\_buffer.c 提供流缓冲区和消息缓冲区功能，如本书后续所述。仅当应用使用流缓冲区或消息缓冲区时才需要构建。

- **croutine.c**

   croutine.c 实现 FreeRTOS 协程功能。仅当应用使用协程时才需要构建。协程旨在用于非常小的微控制器，现在很少使用。因此，它们不再维护，也不建议在新设计中使用。本书不描述协程。

<a id="226-freertos-source-files-specific-to-a-port"></a>
### 2.2.6 特定于移植版的 FreeRTOS 源文件

FreeRTOS/Source/portable 目录包含特定于 FreeRTOS 移植版的源文件。portable 目录按层次结构组织，首先按编译器，然后按处理器架构。图 2.3 显示了该层次结构。

要在使用编译器 '*compiler*' 的处理器架构 '*architecture*' 上运行 FreeRTOS，除了核心 FreeRTOS 源文件外，还必须构建位于 FreeRTOS/Source/portable/\[*compiler*\]/\[*architecture*\] 目录中的文件。

如第 3 章：堆内存管理所述，FreeRTOS 也将堆内存分配视为移植层的一部分。如果 `configSUPPORT_DYNAMIC_ALLOCATION` 设置为 0，则不要在项目中包含堆内存分配方案。

FreeRTOS 在 FreeRTOS/Source/portable/MemMang 目录中提供了示例堆分配方案。如果 FreeRTOS 配置为使用动态内存分配，则必须在项目中包含该目录中的一个堆实现源文件，或者提供您自己的实现。

> **! 不要在项目中包含多个示例堆分配实现。**

<a id="227-include-paths"></a>
### 2.2.7 包含路径

FreeRTOS 需要在编译器的包含路径中包含三个目录。它们是：

1. 核心 FreeRTOS 内核头文件的路径：FreeRTOS/Source/include。

2. 所使用的 FreeRTOS 移植版特定源文件的路径：FreeRTOS/Source/portable/\[*compiler*\]/\[*architecture*\]。

3. 正确的 FreeRTOSConfig.h 头文件的路径。

<a id="228-header-files"></a>
### 2.2.8 头文件

使用 FreeRTOS API 的源文件必须包含 FreeRTOS.h，然后包含包含 API 函数原型的头文件——task.h、queue.h、semphr.h、timers.h、event_groups.h、stream_buffer.h、message_buffer.h 或 croutine.h。不要显式包含任何其他 FreeRTOS 头文件——FreeRTOS.h 会自动包含 FreeRTOSConfig.h。

<a id="23-demo-applications"></a>
## 2.3 演示应用

每个 FreeRTOS 移植版至少附带一个演示应用，在创建时，该应用"开箱即用"，没有编译器错误或警告。如果后续构建工具的更改导致情况不再如此，请使用 FreeRTOS 支持论坛 (<https://forums.FreeRTOS.org>) 告知我们。

> **跨平台支持**：FreeRTOS 在 Windows、Linux 和 MacOS 系统上以及使用各种工具链（包括嵌入式和传统工具链）进行开发和测试。但是，偶尔会由于版本差异或测试遗漏而出现构建错误。请使用 FreeRTOS 支持论坛 (<https://forums.FreeRTOS.org>) 提醒我们任何此类错误。

演示应用有以下几个目的：

- 提供一个可工作的预配置项目示例，包含正确的文件并设置了正确的编译器选项。
- 允许以最少的设置或预先知识进行"开箱即用"的实验。
- 演示如何使用 FreeRTOS API。
- 作为创建实际应用的基础。
- 对内核实现进行压力测试。

每个演示项目位于 FreeRTOS/Demo 目录下的唯一子目录中。子目录的名称指示了该演示项目所对应的移植版。

FreeRTOS.org 网站为每个演示应用包含一个页面。该网页包含以下信息：

- 如何在 FreeRTOS 目录结构中定位演示的项目文件。
- 项目配置使用的硬件或仿真器。
- 如何设置硬件以运行演示。
- 如何构建演示。
- 演示的预期行为。

所有演示项目都创建了"通用演示任务"的一个子集，其实现位于 FreeRTOS/Demo/Common/Minimal 目录中。通用演示任务的存在是为了演示如何使用 FreeRTOS API 和测试 FreeRTOS 内核移植版——它们不实现任何特别有用的功能。

许多演示项目还可以配置为创建一个简单的"blinky"风格入门项目，通常创建两个 RTOS 任务和一个队列。

每个演示项目都包含一个名为 main.c 的文件，其中包含 `main()` 函数，该函数在启动 FreeRTOS 内核之前创建演示应用任务。有关该演示的特定信息，请参阅各个 main.c 文件中的注释。

## 2.4 创建 FreeRTOS 项目

<a id="241-adapting-one-of-the-supplied-demo-projects"></a>
### 2.4.1 改编提供的演示项目之一

每个 FreeRTOS 移植版至少附带一个预配置的演示应用。建议通过改编这些现有项目之一来创建新项目，以确保新项目包含正确的文件、安装正确的中断处理程序以及设置正确的编译器选项。

要从现有演示项目创建新应用：

1. 打开提供的演示项目，确保它按预期构建和执行。

2. 移除实现演示任务的源文件，这些文件位于 Demo/Common 目录中。

3. 删除 `main()` 中除 `prvSetupHardware()` 和 `vTaskStartScheduler()` 之外的所有函数调用，如清单 2.1 所示。

4. 验证项目仍然可以构建。

按照这些步骤操作时，您创建的项目包含正确的 FreeRTOS 源文件，但未定义任何功能。

<a name="list2.1" title="清单 2.1 新 main() 函数的模板"></a>

```c
int main( void )
{
    /* 执行必要的硬件设置。 */
    prvSetupHardware();

    /* --- 可以在此处创建应用任务 --- */

    /* 启动已创建的任务运行。 */
    vTaskStartScheduler();

    /* 只有当堆不足以启动调度器时，执行才会到达此处。 */
    for( ;; );
    return 0;
}
```
***清单 2.1*** *新 main() 函数的模板*

<a id="242-creating-a-new-project-from-scratch"></a>
### 2.4.2 从头创建新项目

如前所述，建议从现有演示项目创建新项目。如果不想这样做，则使用以下过程创建新项目：

1. 使用您选择的工具链，创建一个尚不包含任何 FreeRTOS 源文件的新项目。

1. 确保新项目可以构建、下载到目标硬件并执行。

1. 只有在确定已经有一个可工作的项目后，才将表 1 中详述的 FreeRTOS 源文件添加到项目中。

1. 将演示项目使用并为所用移植版提供的 `FreeRTOSConfig.h` 头文件复制到新项目目录中。

1. 将以下目录添加到项目搜索头文件的路径中：

   - FreeRTOS/Source/include
   - FreeRTOS/Source/portable/\[*compiler*\]/\[*architecture*\]（其中 \[*compiler*\] 和 \[*architecture*\] 适用于您选择的移植版）
   - 包含 `FreeRTOSConfig.h` 头文件的目录

1. 从相关演示项目复制编译器设置。

1. 安装任何可能需要的 FreeRTOS 中断处理程序。使用描述所用移植版和为该移植版提供的演示项目的网页作为参考。

<a id="25-data-types-and-coding-style-guide"></a>
## 2.5 数据类型和编码风格指南

<a id="251-data-types"></a>
### 2.5.1 数据类型

FreeRTOS 的每个移植版都有一个唯一的 portmacro.h 头文件，其中包含（除其他内容外）两个特定于移植版的数据类型的定义：`TickType_t` 和 `BaseType_t`。以下列表描述了使用的宏或 typedef 以及实际类型：

- `TickType_t`

  FreeRTOS 配置一个称为滴答中断的周期性中断。

  自 FreeRTOS 应用启动以来发生的滴答中断次数称为*滴答计数*。滴答计数用作时间度量。

  两个滴答中断之间的时间称为*滴答周期*。时间被指定为滴答周期的倍数。

  `TickType_t` 是用于保存滴答计数值和指定时间的数据类型。

  `TickType_t` 可以是无符号 16 位类型、无符号 32 位类型或无符号 64 位类型，具体取决于 FreeRTOSConfig.h 中 `configTICK_TYPE_WIDTH_IN_BITS` 的设置。`configTICK_TYPE_WIDTH_IN_BITS` 的设置依赖于架构。FreeRTOS 移植版也会检查此设置是否有效。

  在 8 位和 16 位架构上使用 16 位类型可以大大提高效率，但会严重限制 FreeRTOS API 调用中可指定的最大阻塞时间。在 32 位或 64 位架构上没有理由使用 16 位的 `TickType_t` 类型。

  以前使用的 `configUSE_16_BIT_TICKS` 已被 `configTICK_TYPE_WIDTH_IN_BITS` 取代，以支持大于 32 位的滴答计数。新设计应使用 `configTICK_TYPE_WIDTH_IN_BITS` 而不是 `configUSE_16_BIT_TICKS`。

   <a name="tbl2" title="表 2 TickType_t 数据类型和 configTICK_TYPE_WIDTH_IN_BITS 配置"></a>

   * * *
   | configTICK\_TYPE\_WIDTH\_IN\_BITS | 8 位架构 | 16 位架构 | 32 位架构 | 64 位架构 |
   | --- | --- | --- | --- | --- |
   | TICK\_TYPE\_WIDTH\_16_BITS | uint16\_t | uint16\_t | uint16\_t | 不适用 |
   | TICK\_TYPE\_WIDTH\_32_BITS | uint32\_t | uint32\_t | uint32\_t | 不适用 |
   | TICK\_TYPE\_WIDTH\_64_BITS | 不适用 | 不适用 | uint64\_t | uint64\_t |

   ***表 2*** *TickType_t 数据类型和 configTICK_TYPE_WIDTH_IN_BITS 配置*
   * * *

- `BaseType_t`

  这始终定义为该架构最高效的数据类型。通常，在 64 位架构上为 64 位类型，在 32 位架构上为 32 位类型，在 16 位架构上为 16 位类型，在 8 位架构上为 8 位类型。

  `BaseType_t` 通常用于取值范围非常有限的返回类型，以及用于 `pdTRUE`/`pdFALSE` 类型的布尔值。

*FreeRTOS 使用的特定于移植版的数据类型列表*

<a id="252-variable-names"></a>
### 2.5.2 变量命名

变量以其类型为前缀：'c' 表示 `char`，'s' 表示 `int16_t`（短整型），'l' 表示 `int32_t`（长整型），'x' 表示 `BaseType_t` 和任何其他非标准类型（结构体、任务句柄、队列句柄等）。

如果变量是无符号的，还要加上 'u' 前缀。如果变量是指针，还要加上 'p' 前缀。例如，`uint8_t` 类型的变量将以 'uc' 为前缀，而指向 char 的指针类型（`char *`）的变量将以 'pc' 为前缀。

<a id="253-function-names"></a>
### 2.5.3 函数命名

函数以其返回类型和定义所在的文件为前缀。例如：

- v**Task**PrioritySet() 返回 *v*oid（空），定义在 **tasks**.c 中。
- x**Queue**Receive() 返回 *BaseType_t* 类型的变量，定义在 **queue**.c 中。
- pv**Timer**GetTimerID() 返回指向 *v*oid 的 *p*ointer（指针），定义在 **timers**.c 中。

文件作用域（私有）函数以 'prv' 为前缀。

<a id="254-formatting"></a>
### 2.5.4 格式

在某些演示应用中使用制表符，其中一个制表符始终设置为等于四个空格。内核不再使用制表符。

<a id="256-rationale-for-excessive-type-casting"></a>
### 2.5.6 过度类型转换的理由

FreeRTOS 源代码需要在许多不同的编译器上编译，这些编译器在生成警告的方式和时间上各不相同。特别是，不同的编译器要求以不同的方式使用类型转换。因此，FreeRTOS 源代码包含的类型转换比通常需要的要多。
