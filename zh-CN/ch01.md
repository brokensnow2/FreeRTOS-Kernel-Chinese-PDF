## 1.1 小型嵌入式系统中的多任务处理

<a id="111-about-the-freertos-kernel"></a>

### 1.1.1 关于 FreeRTOS 内核

FreeRTOS 是一组 C 语言库，由一个实时内核以及一组用于实现补充功能的模块化库组成。

Richard Barry 于 2003 年前后开始开发 FreeRTOS。此后，他创办的 Real-Time Engineers Ltd 与世界领先的芯片公司密切合作，持续推进 FreeRTOS 的开发，直到 Amazon Web Services（AWS）于 2016 年接管 FreeRTOS 的维护工作。如今，Richard 仍在 AWS IoT 团队担任高级首席工程师，继续从事 FreeRTOS 相关工作。FreeRTOS 是采用 MIT 许可证的开源软件，可用于任何用途。即使不是 AWS 客户，也能受益于 AWS 对 FreeRTOS 的维护。

FreeRTOS 内核非常适合运行在微控制器或小型微处理器上的深度嵌入式实时应用。这类应用通常同时包含硬实时要求和软实时要求。

软实时要求规定了一个时间期限，但即使超过期限，系统也不会因此完全失效。例如，对按键操作的响应过慢，可能会让人觉得系统反应迟钝，却不至于使系统无法使用。

硬实时要求同样规定了一个时间期限，但一旦超过期限，系统便会彻底失败。例如，如果驾驶员安全气囊对碰撞传感器输入的响应过慢，它造成的伤害可能反而大于所能提供的保护。

FreeRTOS 内核是一种实时内核（也称实时调度器），它帮助基于 FreeRTOS 构建的应用满足硬实时要求。应用可以被组织为一组相互独立的执行线程。例如，在只有一个内核的处理器上，任意时刻只能有一个执行线程运行。内核通过检查应用设计者为各线程分配的优先级，决定当前应运行哪个线程。最简单的做法是，为实现硬实时要求的线程分配较高优先级，为实现软实时要求的线程分配较低优先级。这样可以确保硬实时线程总是先于软实时线程运行，但实际的优先级分配决策并不总是如此简单。

即使你现在还没有完全理解上一段中的概念，也不必担心。后续章节将通过详细说明和大量示例，帮助你理解如何使用实时内核，尤其是如何使用 FreeRTOS。

<a id="113-a-note-about-terminology"></a>

### 1.1.3 关于术语的说明

在 FreeRTOS 中，每个执行线程都称为“任务”（task）。嵌入式社区对相关术语并没有统一约定，但我更倾向于使用“任务”而不是“线程”，因为“线程”在某些应用领域中可能具有更加特定的含义。

<a id="114-why-use-an-rtos"></a>

### 1.1.4 为什么使用 RTOS？

即使不使用多线程内核，也有许多成熟的方法可以编写出优秀的嵌入式软件。如果正在开发的系统比较简单，这些方法可能才是最合适的选择。对于更复杂的系统，使用内核通常更为合适，但复杂到什么程度才需要跨过这条分界线，始终是一个主观判断。

如前所述，任务优先级有助于确保应用满足处理时限，但内核还会带来一些不那么显而易见的好处。下面对其中部分好处作简要说明。

- **抽象时间信息**

  RTOS 负责控制执行时序，并向应用提供与时间相关的 API。这样可以让应用代码的结构更加直接，同时缩小整体代码规模。

- **可维护性和可扩展性**

  将时序细节抽象出来，可以减少模块之间的相互依赖，使软件能够以可控且可预测的方式演进。此外，由内核负责时序后，底层硬件的变化也不容易影响应用性能。

- **模块化**

  各个任务都是相互独立的模块，并且每个任务都应具有明确的用途。

- **团队开发**

  各个任务还应具有定义清晰的接口，从而降低团队协作开发的难度。

- **更易测试**

  定义明确、相互独立且接口清晰的任务模块，更容易进行隔离测试。

- **代码复用**

  模块化程度越高、相互依赖越少，代码就越容易复用。

- **提高效率**

  使用 RTOS 的应用代码可以完全由事件驱动，因此不必把处理时间浪费在轮询尚未发生的事件上。

  与事件驱动带来的效率提升相对应，系统需要处理 RTOS 时钟节拍中断，并在不同任务之间切换执行。不过，不使用 RTOS 的应用通常也会包含某种形式的时钟节拍中断。

- **空闲时间**

  当没有应用任务需要处理时，系统自动创建的空闲任务会开始运行。空闲任务可以用来测量剩余处理能力、执行后台检查，或者让处理器进入低功耗模式。

- **电源管理**

  使用 RTOS 带来的效率提升，使处理器能够在低功耗模式中停留更长时间。

  每当空闲任务运行时，都可以让处理器进入低功耗状态，从而显著降低功耗。FreeRTOS 还提供一种特殊的无时钟节拍模式。使用该模式后，处理器可以进入比通常情况下更低的功耗状态，并在低功耗状态中停留更长时间。

- **灵活的中断处理**

  可以将具体处理工作延后，交给应用开发者创建的任务，或者交给系统自动创建的 RTOS 守护任务（也称定时器服务任务），从而让中断处理程序保持非常简短。

- **混合处理要求**

  通过简单的设计模式，可以在同一个应用中实现周期处理、连续处理和事件驱动处理。通过选择合适的任务优先级和中断优先级，还可以同时满足硬实时要求和软实时要求。

<a id="115-freertos-kernel-features"></a>

### 1.1.5 FreeRTOS 内核的功能

FreeRTOS 内核具备以下标准功能：

- 支持抢占式或协作式运行
- 可选的时间片调度
- 非常灵活的任务优先级分配
- 灵活、快速且轻量的任务通知机制
- 队列
- 二值信号量
- 计数信号量
- 互斥量
- 递归互斥量
- 软件定时器
- 事件组
- 流缓冲区
- 消息缓冲区
- 协程（已弃用）
- 时钟节拍钩子函数
- 空闲任务钩子函数
- 栈溢出检查
- 跟踪宏
- 任务运行时间统计
- 可选的商业许可与支持
- 完整的中断嵌套模型（适用于部分架构）
- 面向超低功耗应用的无时钟节拍功能（适用于部分架构）
- 使用内存保护单元隔离任务并提高应用安全性（适用于部分架构）
- 在适当情况下使用软件管理的中断栈，这有助于节省 RAM
- 可以使用静态分配或动态分配的内存创建 RTOS 对象

<a id="116-licensing-and-the-freertos-openrtos-and-safertos-family"></a>

### 1.1.6 许可，以及 FreeRTOS、OpenRTOS 和 SafeRTOS 产品系列

**FreeRTOS** 采用 MIT 开源许可证，其设计目标是确保：

- FreeRTOS 可以用于商业应用。
- FreeRTOS 本身始终可以由所有人免费获得。
- FreeRTOS 用户保留其知识产权的所有权。

最新的开源许可信息请参阅 <https://www.FreeRTOS.org/license>。

**OpenRTOS** 是 FreeRTOS 的商业许可版本，由第三方获得 Amazon Web Services 授权后提供。

**SafeRTOS** 与 FreeRTOS 采用相同的使用模型，但其开发遵循了声明符合多项国际公认安全相关标准所必需的实践、规程和流程。
