## 1.1 小型嵌入式系统中的多任务处理

<a id="111-about-the-freertos-kernel"></a>
### 1.1.1 关于 FreeRTOS 内核

FreeRTOS 是一个 C 语言库的集合，由一个实时内核和一组实现补充功能的模块化库组成。

Richard Barry 于 2003 年左右最初开发了 FreeRTOS。Richard 的公司 Real-Time Engineers Ltd 与全球领先的芯片公司紧密合作，持续开发 FreeRTOS，直到亚马逊网络服务（AWS）于 2016 年接管 FreeRTOS 的管理工作。Richard 现在作为 AWS IoT 团队的高级首席工程师，继续他在 FreeRTOS 上的工作。FreeRTOS 是采用 MIT 许可证的开源代码，可用于任何目的。您不必成为 AWS 客户也能从 AWS 的管理中受益！

FreeRTOS 内核非常适合运行在微控制器或小型微处理器上的深度嵌入式实时应用。这类应用通常同时包含硬实时和软实时需求。

软实时需求规定了时间截止期限——但超出截止期限不会导致系统完全失效。例如，响应按键速度太慢可能会让系统显得迟钝而令人烦恼，但实际上并不会使其无法使用。

硬实时需求规定了时间截止期限——而超出截止期限将导致系统完全失效。例如，安全气囊如果对碰撞传感器输入的响应太慢，可能弊大于利。

FreeRTOS 内核是一个实时内核（或实时调度器），使基于 FreeRTOS 构建的应用能够满足其硬实时需求。它允许应用被组织为独立的执行线程集合。例如，在只有一个内核的处理器上，任何时刻只能执行一个线程。内核通过检查应用设计者为每个线程分配的优先级来决定执行哪个线程。在最简单的情况下，应用设计者可以为实现硬实时需求的线程分配较高的优先级，而为实现软实时需求的线程分配较低的优先级。以这种方式分配优先级可以确保硬实时线程始终在软实时线程之前执行，但优先级分配的决策并不总是如此简单。

如果您尚未完全理解上一段中的概念，不必担心。后续章节将通过大量示例提供详细解释，帮助您理解如何使用实时内核，特别是 FreeRTOS。

<a id="113-a-note-about-terminology"></a>
### 1.1.3 关于术语的说明

在 FreeRTOS 中，每个执行线程被称为一个"任务"。嵌入式社区对术语没有共识，但我更喜欢"任务"而非"线程"，因为"线程"在某些应用领域中可能具有更具体的含义。

<a id="114-why-use-an-rtos"></a>
### 1.1.4 为什么要使用 RTOS？

有许多成熟的技术可以在不使用多线程内核的情况下编写良好的嵌入式软件。如果正在开发的系统很简单，那么这些技术可能提供最合适的解决方案。在更复杂的情况下，使用内核可能更可取，但交叉点在哪里总是主观的。

如前所述，任务优先级划分可以帮助确保应用满足其处理截止期限，但内核还可以带来其他不那么明显的益处。下面简要列出其中一些。

- 抽象化时间信息

  RTOS 负责执行时序，并向应用提供与时间相关的 API。这使得应用代码的结构更加简单，整体代码量更小。

- 可维护性/可扩展性

  抽象化时间细节减少了模块间的相互依赖，并允许软件以可控和可预测的方式演进。此外，由于内核负责时序，应用性能不易受底层硬件变化的影响。

- 模块化

  任务是独立的模块，每个任务应有明确的目的。

- 团队开发

  任务还应有明确的接口，从而更容易进行团队开发。

- 更易测试

  具有清晰接口的定义良好的独立模块更容易进行隔离测试。

- 代码复用

  具有更高模块化和更少相互依赖性的设计代码更容易复用。

- 提高效率

  使用 RTOS 的应用代码可以完全采用事件驱动。无需浪费处理时间来轮询尚未发生的事件。

  与事件驱动带来的效率相对的是需要处理 RTOS 滴答中断以及将执行从一个任务切换到另一个任务。然而，不使用 RTOS 的应用通常也会包含某种形式的滴答中断。

- 空闲时间

  当没有应用任务需要处理时，自动创建的空闲任务会执行。空闲任务可以测量空闲处理能力、执行后台检查或将处理器置于低功耗模式。

- 电源管理

  使用 RTOS 带来的效率提升使处理器能够花更多时间处于低功耗模式。

  每次空闲任务运行时将处理器置于低功耗状态，可以显著降低功耗。FreeRTOS 还具有特殊的无滴答模式。使用无滴答模式允许处理器进入比其他方式更低的功耗模式，并在低功耗模式下停留更长时间。

- 灵活的中断处理

  通过将处理推迟到应用编写者创建的任务或自动创建的 RTOS 守护任务（也称为定时器任务），中断处理程序可以保持非常简短。

- 混合处理需求

  简单的设计模式可以在应用中实现周期性、连续性和事件驱动处理的混合。此外，通过选择合适的任务和中断优先级，可以满足硬实时和软实时需求。

<a id="115-freertos-kernel-features"></a>
### 1.1.5 FreeRTOS 内核特性

FreeRTOS 内核具有以下标准特性：

- 抢占式或协作式操作
- 可选的时间片轮转
- 非常灵活的任务优先级分配
- 灵活、快速且轻量级的任务通知机制
- 队列
- 二值信号量
- 计数信号量
- 互斥量
- 递归互斥量
- 软件定时器
- 事件组
- 流缓冲区
- 消息缓冲区
- 协程（已弃用）
- 滴答钩子函数
- 空闲钩子函数
- 栈溢出检查
- 跟踪宏
- 任务运行时统计信息收集
- 可选的商业许可和支持
- 完整的中断嵌套模型（对于某些架构）
- 用于极端低功耗应用的无滴答能力（对于某些架构）
- 用于隔离任务和提高应用安全性的内存保护单元支持（对于某些架构）
- 适当时的软件管理中断栈（这有助于节省 RAM）
- 使用静态或动态分配内存创建 RTOS 对象的能力

### 1.1.6 许可，以及 FreeRTOS、OpenRTOS 和 SafeRTOS 系列

**FreeRTOS** MIT 开源许可证旨在确保：

- FreeRTOS 可用于商业应用。

- FreeRTOS 本身对所有人保持免费可用。

- FreeRTOS 用户保留其知识产权所有权。

请参阅 <https://www.FreeRTOS.org/license> 获取最新的开源许可证信息。

**OpenRTOS** 是 FreeRTOS 的商业许可版本，由第三方在亚马逊网络服务的许可下提供。

**SafeRTOS** 与 FreeRTOS 共享相同的使用模型，但已按照必要的实践、程序和流程进行开发，以声明符合各种国际公认的安全相关标准。
