# 5 队列管理

<a id="51-introduction"></a>
## 5.1 引言

“队列”提供了任务到任务、任务到中断以及中断到任务的通信机制。

<a id="511-scope"></a>
### 5.1.1 范围

本章涵盖：

- 如何创建队列。
- 队列如何管理其包含的数据。
- 如何向队列发送数据。
- 如何从队列接收数据。
- 在队列上阻塞的含义。
- 如何在多个队列上阻塞。
- 如何覆盖队列中的数据。
- 如何清空队列。
- 任务优先级在读写队列时的影响。

本章仅讨论任务到任务的通信。第 7 章将介绍任务到中断以及中断到任务的通信。

<a id="52-characteristics-of-a-queue"></a>
## 5.2 队列的特性

<a id="521-data-storage"></a>
### 5.2.1 数据存储

一个队列可以容纳有限数量、大小固定的数据项[^8]。队列最多能够容纳的数据项数量称为队列的“长度”。队列长度和每个数据项的大小都在创建队列时确定。

[^8]: FreeRTOS 消息缓冲区将在后续章节介绍。对于长度可变的消息，它是比队列更轻量的替代方案。

队列通常用作先进先出（FIFO）缓冲区：数据写入队列尾部，并从队列头部移除。图 5.1 演示了向 FIFO 队列写入数据以及从中读取数据的过程。也可以把数据写入队列头部，或覆盖队列头部已有的数据。

队列行为可以通过两种方式实现：

1. 按值复制入队

    按值复制入队是指将发送的数据逐字节复制到队列中。

1. 按引用入队

    按引用入队是指队列只保存指向数据的指针，而不保存数据本身。

FreeRTOS 采用按值复制入队，因为它比按引用入队功能更强，也更易于使用：

- 按值复制并不妨碍队列用于按引用入队。例如，数据太大、不适合直接复制进队列时，可以改为把指向数据的指针复制进队列。

- 栈变量可以直接发送到队列，即使该变量在其声明的函数退出后将不再存在。

- 可以直接向队列发送数据，无需先分配缓冲区、把数据复制到缓冲区，再将缓冲区的引用入队。

- 发送任务可以立即重用发送给队列的变量或缓冲区。

- 发送任务和接收任务完全解耦；应用程序设计者无需考虑哪个任务“拥有”数据，也无需决定由哪个任务负责释放数据。

- RTOS 完全负责分配用于保存数据的内存。

- 在具有内存保护的系统中，对 RAM 的访问会受到限制。只有发送任务和接收任务都能访问被引用的数据时，按引用入队才可行；按值复制则允许数据跨越内存保护边界传递。

<a id="522-access-by-multiple-tasks"></a>
### 5.2.2 多个任务访问

队列本身是一种对象，任何知道该队列存在的任务或 ISR 都可以访问它。任意数量的任务可以写入同一队列，也可以从同一队列读取。实际应用中，一个队列有多个写入者很常见，但有多个读取者则少见得多。

<a id="523-blocking-on-queue-reads"></a>
### 5.2.3 在队列读取时阻塞

任务尝试从队列读取数据时，可以选择指定“阻塞时间”。如果队列为空，任务会在这段时间内保持 *阻塞* 状态，等待队列中出现可用数据。另一个任务或中断把数据放入队列后，等待该数据的任务会自动转入 *就绪* 状态。如果数据出现前阻塞时间已经到期，任务同样会自动从 *阻塞* 状态转入 *就绪* 状态。

一个队列可以有多个读取者，因此可能有多个任务同时阻塞在同一队列上等待数据。数据到达时只会解除一个任务的阻塞，所选择的是等待任务中优先级最高的任务。如果两个或多个阻塞任务优先级相同，则解除等待时间最长的任务。

<a id="524-blocking-on-queue-writes"></a>
### 5.2.4 在队列写入时阻塞

与读取队列相同，任务写入队列时也可以指定阻塞时间。如果队列已满，该时间表示任务保持 *阻塞* 状态、等待队列出现可用空间的最长时间。

一个队列可以有多个写入者，因此队列已满时，可能有多个任务阻塞在该队列上等待完成发送操作。队列出现可用空间时只会解除一个任务的阻塞，所选择的是等待任务中优先级最高的任务。如果两个或多个阻塞任务优先级相同，则解除等待时间最长的任务。

<a id="525-blocking-on-multiple-queues"></a>
### 5.2.5 在多个队列上阻塞

多个队列可以组成队列集，使任务能够进入 *阻塞* 状态，等待其中任意队列出现可用数据。第 5.6 节“从多个队列接收数据”将演示队列集的用法。

<a id="526-creating-queues-statically-allocated-and-dynamically-allocated-queues"></a>
### 5.2.6 创建队列：静态分配与动态分配

队列通过句柄引用，句柄是 `QueueHandle_t` 类型的变量。队列必须先显式创建，才能使用。

创建队列有两个 API 函数：`xQueueCreate()` 和 `xQueueCreateStatic()`。

每个队列需要两块 RAM：第一块保存队列的数据结构，第二块保存入队的数据。`xQueueCreate()` 从堆中动态分配所需 RAM；`xQueueCreateStatic()` 则使用通过参数传入的预分配 RAM。

<a id="53-using-a-queue"></a>
## 5.3 使用队列

<a id="531-the-xqueuecreate-api-function"></a>
### 5.3.1 xQueueCreate() API 函数

代码清单 5.1 给出了 `xQueueCreate()` 的函数原型。`xQueueCreateStatic()` 还有两个参数，分别指向预先分配给队列数据结构和数据存储区的内存。

<a name="list5.1" title="代码清单 5.1 xQueueCreate() API 函数原型"></a>

```c
QueueHandle_t xQueueCreate( UBaseType_t uxQueueLength, UBaseType_t uxItemSize );
```
***代码清单 5.1*** *xQueueCreate() API 函数原型*

**xQueueCreate() 参数和返回值：**

- `uxQueueLength`

  所创建的队列在任何时候能容纳的最大项数。

- `uxItemSize`

  可以存储在队列中的每个数据项的大小（以字节为单位）。

- 返回值

  如果返回 `NULL`，说明没有足够的堆内存供 FreeRTOS 分配队列数据结构和存储区，队列创建失败。第 3 章提供了有关 FreeRTOS 堆的更多信息。

  如果返回非 `NULL` 值，则队列创建成功，返回值是新队列的句柄。

`xQueueReset()` API 函数用于把已创建的队列恢复为空队列。

<a id="532-the-xqueuesendtoback-and-xqueuesendtofront-api-functions"></a>
### 5.3.2 xQueueSendToBack() 和 xQueueSendToFront() API 函数

顾名思义，`xQueueSendToBack()` 把数据发送到队列尾部，`xQueueSendToFront()` 则把数据发送到队列头部。

`xQueueSend()` 与 `xQueueSendToBack()` 完全等价。

> *注意：切勿在中断服务程序中调用 `xQueueSendToFront()` 或 `xQueueSendToBack()`。应改用中断安全版本 `xQueueSendToFrontFromISR()` 和 `xQueueSendToBackFromISR()`。第 7 章将介绍这些函数。*

<a name="list5.2" title="代码清单 5.2 xQueueSendToFront() API 函数原型"></a>

```c
BaseType_t xQueueSendToFront( QueueHandle_t xQueue,
                              const void * pvItemToQueue,
                              TickType_t xTicksToWait );
```
***代码清单 5.2*** *xQueueSendToFront() API 函数原型*

<a name="list5.3" title="代码清单 5.3 xQueueSendToBack() API 函数原型"></a>

```c
BaseType_t xQueueSendToBack( QueueHandle_t xQueue,
                             const void * pvItemToQueue,
                             TickType_t xTicksToWait );
```
***代码清单 5.3*** *xQueueSendToBack() API 函数原型*

**xQueueSendToFront() 和 xQueueSendToBack() 函数参数和返回值**

- `xQueue`

  接收待发送（写入）数据的队列句柄。该句柄由创建队列时调用的 `xQueueCreate()` 或 `xQueueCreateStatic()` 返回。

- `pvItemToQueue`

  指向待复制进队列的数据。

  创建队列时已经设定每个数据项的大小，因此函数会从 `pvItemToQueue` 指向的位置复制相应字节数到队列存储区。

- `xTicksToWait`

  队列已满时，任务保持 *阻塞* 状态、等待队列出现可用空间的最长时间。

  如果 `xTicksToWait` 为 0 且队列已满，`xQueueSendToFront()` 和 `xQueueSendToBack()` 都会立即返回。

  阻塞时间以 Tick 周期为单位，因此对应的实际时长取决于 Tick 频率。宏 `pdMS_TO_TICKS()` 可将毫秒转换为 Tick 数。

  如果在 `FreeRTOSConfig.h` 中将 `INCLUDE_vTaskSuspend` 设置为 1，再把 `xTicksToWait` 设置为 `portMAX_DELAY`，任务将无限期等待而不会超时。

- 返回值

  有两个可能的返回值：

  - `pdPASS`

    数据成功发送到队列时返回 `pdPASS`。

    如果指定了非零阻塞时间，调用任务可能先进入 *阻塞* 状态等待可用空间，但在阻塞时间到期前成功把数据写入队列。

  - `errQUEUE_FULL`（与 `pdFAIL` 的值相同）

    如果队列已满、无法写入数据，则返回 `errQUEUE_FULL`。

    如果指定了非零阻塞时间，调用任务会进入 *阻塞* 状态，等待另一个任务或中断从队列中腾出空间；但在空间出现之前，指定的阻塞时间已经到期。

<a id="533-the-xqueuereceive-api-function"></a>
### 5.3.3 xQueueReceive() API 函数

`xQueueReceive()` 从队列接收（读取）一个数据项，并将该数据项从队列中移除。

> *注意：切勿在中断服务程序中调用 `xQueueReceive()`。第 7 章将介绍中断安全的 `xQueueReceiveFromISR()` API 函数。*

<a name="list5.4" title="代码清单 5.4 xQueueReceive() API 函数原型"></a>

```c
BaseType_t xQueueReceive( QueueHandle_t xQueue,
                          void * const pvBuffer,
                          TickType_t xTicksToWait );
```
***代码清单 5.4*** *xQueueReceive() API 函数原型*

**xQueueReceive() 函数参数和返回值**

- `xQueue`

  待读取数据的队列句柄。该句柄由创建队列时调用的 `xQueueCreate()` 或 `xQueueCreateStatic()` 返回。

- `pvBuffer`

  指向用于保存接收数据的内存。

  创建队列时已经设定每个数据项的大小。`pvBuffer` 指向的内存必须足以容纳相应的字节数。

- `xTicksToWait`

  队列为空时，任务保持 *阻塞* 状态、等待数据到达队列的最长时间。

  如果 `xTicksToWait` 为 0 且队列为空，`xQueueReceive()` 将立即返回。

  阻塞时间以 Tick 周期为单位，因此对应的实际时长取决于 Tick 频率。宏 `pdMS_TO_TICKS()` 可将毫秒转换为 Tick 数。

  如果在 `FreeRTOSConfig.h` 中将 `INCLUDE_vTaskSuspend` 设置为 1，再把 `xTicksToWait` 设置为 `portMAX_DELAY`，任务将无限期等待而不会超时。

- 返回值

  有两个可能的返回值：

  - `pdPASS`

    成功从队列读取数据时返回 `pdPASS`。

    如果指定了非零阻塞时间，调用任务可能先进入 *阻塞* 状态等待数据，但在阻塞时间到期前成功从队列读到了数据。

  - `errQUEUE_EMPTY`（与 `pdFAIL` 的值相同）

    如果队列为空、无法读取数据，则返回 `errQUEUE_EMPTY`。

    如果指定了非零阻塞时间，调用任务会进入 *阻塞* 状态，等待另一个任务或中断向队列发送数据；但在数据到达之前，阻塞时间已经到期。

---
***示例 5.1*** *从队列接收时阻塞*

---

本示例演示如何创建队列、由多个任务向队列发送数据，以及从队列接收数据。队列用于保存 `int32_t` 类型的数据项。发送任务不指定阻塞时间，接收任务则指定阻塞时间。

发送任务的优先级低于接收任务。因此，队列中不会同时存在多个数据项：数据一进入队列，较高优先级的接收任务就会解除阻塞并抢占发送任务，随后取出数据，使队列再次变为空。

本示例创建代码清单 5.6 所示任务的两个实例：一个持续向队列写入值 100，另一个持续向同一队列写入值 200。这两个值通过任务参数传给相应的任务实例。

<a name="list5.6" title="代码清单 5.6 示例 5.1 使用的发送任务实现"></a>

```c
static void vSenderTask( void *pvParameters )
{

    int32_t lValueToSend;

    BaseType_t xStatus;

    /* 本任务会创建两个实例。待发送到队列的值通过任务参数传入，
       因而每个实例可以使用不同的值。队列用于保存 int32_t 类型的值，
       所以需要把参数转换为相应类型。 */
    lValueToSend = ( int32_t ) pvParameters;

    /* 与大多数任务一样，本任务在无限循环中实现。 */
    for( ;; )
    {

        /* 把值发送到队列。

           第一个参数是接收数据的队列。该队列在调度器启动之前创建，
           因而也早于本任务开始执行。

           第二个参数是待发送数据的地址，此处为 lValueToSend 的地址。

           第三个参数是阻塞时间，即队列已满时，任务为等待可用空间而
           保持阻塞状态的时间。本例不指定阻塞时间，因为队列中不应
           同时存在多个数据项，因此也不应变满。 */
        xStatus = xQueueSendToBack( xQueue, &lValueToSend, 0 );

        if( xStatus != pdPASS )
        {
            /* 队列已满，发送操作无法完成。队列中本不应同时存在
               多个数据项，因此这一定是错误。 */
            vPrintString( "Could not send to the queue.\r\n" );
        }
    }
}
```
***代码清单 5.6*** *示例 5.1 使用的发送任务实现*

代码清单 5.7 给出了接收任务的实现。该任务指定 100 毫秒的阻塞时间，并进入 *阻塞* 状态等待数据。当队列中出现数据，或等待 100 毫秒后仍无数据时，任务都会离开 *阻塞* 状态。本示例有两个任务持续写入队列，因此不会发生 100 毫秒超时。

<a name="list5.7" title="代码清单 5.7 示例 5.1 的接收任务实现"></a>

```c
static void vReceiverTask( void *pvParameters )
{
    /* 声明用于保存队列接收值的变量。 */
    int32_t lReceivedValue;
    BaseType_t xStatus;
    const TickType_t xTicksToWait = pdMS_TO_TICKS( 100 );

    /* 本任务同样在无限循环中实现。 */
    for( ;; )
    {
        /* 本任务会立即移除写入队列的所有数据，因此此处队列应始终为空。 */
        if( uxQueueMessagesWaiting( xQueue ) != 0 )
        {
            vPrintString( "Queue should have been empty!\r\n" );
        }

        /* 从队列接收数据。

           第一个参数是读取数据的队列。该队列在调度器启动之前创建，
           因而也早于本任务首次运行。

           第二个参数是保存接收数据的缓冲区。此处直接使用一个大小
           足以保存接收数据的变量地址。

           最后一个参数是阻塞时间，即队列为空时，任务为等待数据而
           保持阻塞状态的最长时间。 */
        xStatus = xQueueReceive( xQueue, &lReceivedValue, xTicksToWait );

        if( xStatus == pdPASS )
        {
            /* 已成功从队列接收数据，打印接收到的值。 */
            vPrintStringAndNumber( "Received = ", lReceivedValue );
        }
        else
        {
            /* 等待 100 毫秒后仍未从队列接收到数据。发送任务会持续运行
               并不断写入队列，因此这一定是错误。 */
            vPrintString( "Could not receive from the queue.\r\n" );
        }
    }
}
```
***代码清单 5.7*** *示例 5.1 的接收任务实现*

代码清单 5.8 给出了 `main()` 函数。它创建队列和三个任务，然后启动调度器。队列最多可以容纳五个 `int32_t` 值，不过由于任务的相对优先级，队列中实际不会同时存在多个数据项。

<a name="list5.8" title="代码清单 5.8 示例 5.1 的 main() 实现"></a>

```c
/* 声明 QueueHandle_t 类型的变量，用于保存三个任务共同访问的队列句柄。 */
QueueHandle_t xQueue;

int main( void )
{
    /* 创建最多可保存 5 个 int32_t 类型值的队列。 */
    xQueue = xQueueCreate( 5, sizeof( int32_t ) );

    if( xQueue != NULL )
    {
        /* 创建两个发送任务实例。通过任务参数传入写入队列的值，
           因而一个任务持续写入 100，另一个任务持续写入 200。
           两个任务的优先级均为 1。 */
        xTaskCreate( vSenderTask, "Sender1", 1000, ( void * ) 100, 1, NULL );
        xTaskCreate( vSenderTask, "Sender2", 1000, ( void * ) 200, 1, NULL );

        /* 创建读取队列的任务。其优先级为 2，高于发送任务。 */
        xTaskCreate( vReceiverTask, "Receiver", 1000, NULL, 2, NULL );

        /* 启动调度器，使已创建的任务开始执行。 */
        vTaskStartScheduler();
    }
    else
    {
        /* 队列创建失败。 */
    }

    /* 如果一切正常，调度器会持续运行任务，main() 不会执行到这里。
       如果 main() 执行到这里，很可能是 FreeRTOS 堆内存不足，无法创建
       空闲任务。第 3 章提供了更多堆内存管理信息。 */
    for( ;; );
}
```

在示例 5.1 中，接收任务的优先级最高，因此队列中的数据项始终不会超过一个。这是因为一旦数据被放入队列，接收任务就会立即抢占发送任务。在示例 5.2 中，发送任务的优先级更高，因此队列通常处于满状态。这是因为接收任务每从队列中移除一个数据项，就会立即被某个发送任务抢占，而该发送任务随即再次填满队列。随后，发送任务重新进入阻塞状态，等待队列再次出现可用空间。

代码清单 5.10 给出了发送任务的实现。发送任务指定了 100 毫秒的阻塞时间，因此每当队列已满时，它都会进入阻塞状态等待可用空间。当队列中出现可用空间，或者等待 100 毫秒后仍无可用空间时，任务将退出阻塞状态。在本例中，接收任务会不断从队列中腾出空间，因此 100 毫秒的超时永远不会发生。

```c
static void vSenderTask( void *pvParameters )
{
    BaseType_t xStatus;
    const TickType_t xTicksToWait = pdMS_TO_TICKS( 100 );

    /* 与大多数任务一样，本任务在无限循环中实现。 */
    for( ;; )
    {
        /* 向队列发送数据。

           第二个参数是待发送结构体的地址。该地址通过任务参数传入，
           因此这里直接使用 pvParameters。

           第三个参数是阻塞时间，即当队列已满时，任务为等待队列出现
           可用空间而保持阻塞状态的时间。这里必须指定阻塞时间，因为
           发送任务的优先级高于接收任务，队列预计会被填满。两个发送
           任务都处于阻塞状态时，接收任务才会从队列中移除数据项。 */
        xStatus = xQueueSendToBack( xQueue, pvParameters, xTicksToWait );

        if( xStatus != pdPASS )
        {
            /* 即使等待了 100 毫秒，发送操作仍未完成。这必定是一个错误，
               因为两个发送任务一旦都进入阻塞状态，接收任务就应当在
               队列中腾出空间。 */
            vPrintString( "Could not send to the queue.\r\n" );
        }
    }
```

接收任务的优先级最低，因此只有两个发送任务都处于阻塞状态时它才会运行。发送任务仅在队列已满时进入阻塞状态，所以接收任务每次执行时，队列都应当是满的。因此，即使不指定阻塞时间，它也始终能够接收到数据。

```c
static void vReceiverTask( void *pvParameters )
{
    /* 声明用于保存从队列接收到的值的结构体。 */
    Data_t xReceivedStructure;
    BaseType_t xStatus;

    /* 本任务同样在无限循环中实现。 */
    for( ;; )
    {
        /* 由于本任务的优先级最低，它只会在发送任务处于阻塞状态时运行。
           发送任务仅在队列已满时进入阻塞状态，因此本任务始终预期队列中
           的数据项数量等于队列长度，本例中该长度为 3。 */
        if( uxQueueMessagesWaiting( xQueue ) != 3 )
        {
            vPrintString( "Queue should have been full!\r\n" );
        }

        /* 从队列接收数据。

           第二个参数是用于存放接收数据的缓冲区。本例中的缓冲区就是一个
           变量的地址，该变量的大小足以容纳接收到的结构体。

           最后一个参数是阻塞时间，即队列为空时，任务为等待数据可用而
           保持阻塞状态的最长时间。本例无须指定阻塞时间，因为本任务只会
           在队列已满时运行。 */
        xStatus = xQueueReceive( xQueue, &xReceivedStructure, 0 );

        if( xStatus == pdPASS )
        {
            /* 已成功从队列接收数据，打印接收到的值及其来源。 */
            if( xReceivedStructure.eDataSource == eSender1 )
            {
                vPrintStringAndNumber( "From Sender 1 = ", 
                                       xReceivedStructure.ucValue );
            }
            else
            {
                vPrintStringAndNumber( "From Sender 2 = ", 
                                       xReceivedStructure.ucValue );
            }
        }
        else
        {
            /* 未从队列接收到任何数据。这必定是一个错误，因为本任务只应
               在队列已满时运行。 */
            vPrintString( "Could not receive from the queue.\r\n" );
        }
    }
}
```

## 5.5 处理大型或长度可变的数据

<a id="551-queuing-pointers"></a>
### 5.5.1 将指针入队

如果要存入队列的数据量很大，最好通过队列传递指向数据的指针，而不是逐字节地将数据本身复制进队列和复制出队列。无论从处理时间还是创建队列所需的 RAM 容量来看，传递指针都更加高效。不过，将指针入队时必须格外谨慎，确保满足以下条件：

- 明确定义所指向 RAM 的所有权。

  通过指针在任务之间共享内存时，必须确保两个任务不会同时修改内存内容，也不会执行任何其他可能使内存内容失效或不一致的操作。理想情况下，指针发送到队列之前，只有发送任务能够访问该内存；从队列接收到指针之后，则只有接收任务能够访问该内存。

- 确保所指向的 RAM 始终有效。

  如果所指向的内存是动态分配的，或取自预先分配的缓冲区池，则应当明确由且仅由一个任务负责释放该内存。内存释放后，任何任务都不得再尝试访问它。

  绝不能通过队列传递指向任务栈上数据的指针，因为栈帧发生变化后，这些数据将不再有效。

代码清单 5.13、5.14 和 5.15 演示了如何使用队列将指向缓冲区的指针从一个任务发送到另一个任务：

- 代码清单 5.13 创建一个最多可容纳五个指针的队列。

- 代码清单 5.14 获取一个缓冲区，向其中写入字符串，然后将指向该缓冲区的指针发送到队列。

- 代码清单 5.15 从队列接收一个指向缓冲区的指针，然后打印缓冲区中的字符串。

<a id="56-receiving-from-multiple-queues"></a>
## 5.6 从多个队列接收数据

<a id="561-queue-sets"></a>
### 5.6.1 队列集

应用程序设计经常要求单个任务接收长度不同、含义不同以及来源不同的数据。上一节演示了如何使用一个接收结构体的队列，以简洁高效的方式满足这一要求。然而，应用程序设计者有时会受到某些约束，无法自由选择设计方案，因而必须为特定数据源使用独立队列。例如，要集成到系统中的第三方代码可能假定存在专用队列。在这种情况下，可以使用“队列集”。

队列集允许任务从多个队列接收数据，而无须逐个轮询队列来判断其中哪个队列包含数据。

与使用单个队列接收结构体的方案相比，使用队列集从多个数据源接收数据不够简洁，效率也更低。因此，建议仅在设计约束确实要求使用队列集时采用这种方案。

以下各节将介绍如何使用队列集：

- 创建队列集。

- 向队列集中添加队列。

  信号量也可以添加到队列集中，本书后续章节将介绍信号量。

- 从队列集读取，以确定其中哪个队列包含数据。

  当队列集中的某个成员队列接收到数据时，该队列的句柄会被发送到队列集，并在任务调用队列集读取函数时返回。因此，只要队列集返回了某个队列句柄，就可以确定该句柄所引用的队列中包含数据，任务随后便可直接读取该队列。

  > *注意：如果一个队列是队列集的成员，那么每次从队列集接收到该队列的句柄后，都必须从该队列读取一个数据项；在从队列集接收到其句柄之前，则不得读取该队列。*

要启用队列集功能，需在 `FreeRTOSConfig.h` 中将编译时配置常量 `configUSE_QUEUE_SETS` 设为 1。

<a id="562-the-xqueuecreateset-api-function"></a>
### 5.6.2 xQueueCreateSet() API 函数

队列集必须在使用前显式创建。在本书编写时，FreeRTOS 尚未实现 `xQueueCreateSetStatic()`。不过，队列集本身也是队列，因此可以通过谨慎构造对 `xQueueCreateStatic()` 的调用，使用预先分配的内存创建队列集。

队列集由句柄引用，该句柄保存在 `QueueSetHandle_t` 类型的变量中。`xQueueCreateSet()` API 函数创建一个队列集，并返回引用所创建队列集的 `QueueSetHandle_t`。

<a name="list5.21" title="代码清单 5.21 xQueueCreateSet() API 函数原型"></a>

```c
QueueSetHandle_t xQueueCreateSet( const UBaseType_t uxEventQueueLength);
```
***代码清单 5.21*** *`xQueueCreateSet()` API 函数原型*

**xQueueCreateSet() 参数和返回值**

- `uxEventQueueLength`

  当队列集中的某个成员队列接收到数据时，该队列的句柄会被发送到队列集。`uxEventQueueLength` 指定所创建的队列集在任意时刻最多能够容纳多少个队列句柄。

  只有当队列集中的队列接收到数据时，该队列的句柄才会被发送到队列集。已满的队列无法再接收数据，因此当队列集中的所有队列都已满时，也不会再有新的队列句柄发送到队列集。由此可知，队列集在任意时刻可能需要容纳的最大数据项数，等于其中所有成员队列的长度之和。

  例如，某个队列集中有三个空队列，每个队列的长度均为 5。这些成员队列总共可以接收十五个数据项（三个队列乘以每个队列五个数据项），之后才会全部填满。在这个例子中，必须将 `uxEventQueueLength` 设为 15，才能保证队列集能够容纳发送给它的每一个句柄。

  信号量也可以添加到队列集中，本书后续章节将介绍信号量。计算所需的 `uxEventQueueLength` 时，二值信号量和互斥量的长度均视为 1，计数信号量的长度则等于其最大计数值。

  再例如，如果一个队列集包含一个长度为 3 的队列和一个二值信号量（长度视为 1），则必须将 `uxEventQueueLength` 设为 4（3 加 1）。

- 返回值

  如果返回 `NULL`，则表示队列集创建失败，因为没有足够的堆内存供 FreeRTOS 分配队列集数据结构和存储区。第 3 章提供了有关 FreeRTOS 堆的更多信息。

  如果返回值不是 `NULL`，则表示队列集创建成功，返回值就是所创建队列集的句柄。

<a id="563-the-xqueueaddtoset-api-function"></a>
### 5.6.3 xQueueAddToSet() API 函数

`xQueueAddToSet()` 将队列或信号量添加到队列集。本书后续章节将介绍信号量。

<a name="list5.22" title="代码清单 5.22 xQueueAddToSet() API 函数原型"></a>

```c
BaseType_t xQueueAddToSet( QueueSetMemberHandle_t xQueueOrSemaphore,
                           QueueSetHandle_t xQueueSet );
```
***代码清单 5.22*** *`xQueueAddToSet()` API 函数原型*

**xQueueAddToSet() 参数和返回值**

- `xQueueOrSemaphore`

  要添加到队列集的队列或信号量句柄。

  队列句柄和信号量句柄都可以强制转换为 `QueueSetMemberHandle_t` 类型。

- `xQueueSet`

  目标队列集的句柄。

- 返回值

  有两个可能的返回值：

  1. `pdPASS`

     表示队列或信号量已成功添加到队列集。

  1. `pdFAIL`

     表示无法将队列或信号量添加到队列集。

  队列和二值信号量只能在为空时添加到队列集；计数信号量只能在计数值为零时添加。一个队列或信号量同一时刻只能属于一个队列集。

<a id="564-the-xqueueselectfromset-api-function"></a>
### 5.6.4 xQueueSelectFromSet() API 函数

`xQueueSelectFromSet()` 从队列集中读取队列或信号量句柄。

当队列集中的某个成员队列或信号量接收到数据时，该成员的句柄会被发送到队列集，并在任务调用 `xQueueSelectFromSet()` 时返回。只要 `xQueueSelectFromSet()` 返回了一个句柄，就可以确定该句柄引用的队列或信号量中有数据可用，调用任务必须随即直接读取该队列或信号量。

> *注意：除非 `xQueueSelectFromSet()` 已经返回了某个成员队列或信号量的句柄，否则不得读取该成员。每当 `xQueueSelectFromSet()` 返回一个成员句柄时，只能从对应的队列或信号量读取一个数据项。*

<a name="list5.23" title="代码清单 5.23 xQueueSelectFromSet() API 函数原型"></a>

```c
QueueSetMemberHandle_t xQueueSelectFromSet( QueueSetHandle_t xQueueSet,
                                            const TickType_t xTicksToWait );
```
***代码清单 5.23*** *`xQueueSelectFromSet()` API 函数原型*

**xQueueSelectFromSet() 参数和返回值**

- `xQueueSet`

  要从中接收（读取）队列或信号量句柄的队列集句柄。该句柄由创建队列集时调用的 `xQueueCreateSet()` 返回。

- `xTicksToWait`

  如果队列集中的所有队列和信号量都为空，该参数指定调用任务为等待队列集返回成员句柄而保持阻塞状态的最长时间。

  如果 `xTicksToWait` 为零，那么当队列集中的所有队列和信号量都为空时，`xQueueSelectFromSet()` 将立即返回。

  阻塞时间以 Tick 周期为单位，因此其对应的绝对时间取决于 Tick 频率。宏 `pdMS_TO_TICKS()` 可将以毫秒为单位的时间转换为 Tick 数。

  如果在 `FreeRTOSConfig.h` 中将 `INCLUDE_vTaskSuspend` 设为 1，那么把 `xTicksToWait` 设为 `portMAX_DELAY` 可使任务无限期等待（永不超时）。

- 返回值

  非 `NULL` 返回值是某个已知有数据可用的队列或信号量的句柄。如果指定了阻塞时间（`xTicksToWait` 不为零），调用任务可能先进入阻塞状态，等待队列集中的队列或信号量有数据可用，并在阻塞时间到期前成功从队列集读取到句柄。返回的句柄类型为 `QueueSetMemberHandle_t`，可以强制转换为 `QueueHandle_t` 或 `SemaphoreHandle_t`。

  如果返回值为 `NULL`，则表示未能从队列集读取到句柄。如果指定了阻塞时间（`xTicksToWait` 不为零），调用任务会进入阻塞状态，等待另一个任务或中断向队列集中的队列或信号量发送数据，但在数据到来之前阻塞时间已经到期。

---
***示例 5.3*** *使用队列集*

---

本例创建两个发送任务和一个接收任务。两个发送任务分别通过各自的队列向接收任务发送数据。这两个队列都被加入同一个队列集，接收任务读取队列集，以确定哪一个队列中包含数据。

任务、队列和队列集都在 `main()` 中创建，具体实现见代码清单 5.24。

<a name="list5.24" title="代码清单 5.24 示例 5.3 中 main() 的实现"></a>

```c
/* 声明两个 QueueHandle_t 类型的变量。两个队列将加入同一个队列集。 */
static QueueHandle_t xQueue1 = NULL, xQueue2 = NULL;

/* 声明一个 QueueSetHandle_t 类型的变量，用于保存两个队列所加入的
   队列集。 */
static QueueSetHandle_t xQueueSet = NULL;

int main( void )
{
    /* 创建两个队列，它们都用于发送字符指针。接收任务的优先级高于发送
       任务，因此任一时刻每个队列中的数据项都不会超过一个。 */
    xQueue1 = xQueueCreate( 1, sizeof( char * ) );
    xQueue2 = xQueueCreate( 1, sizeof( char * ) );

    /* 创建队列集。队列集中将加入两个队列，每个队列可容纳一个数据项，
       因此队列集在任一时刻最多需要保存两个队列句柄（两个队列乘以
       每个队列一个数据项）。 */
    xQueueSet = xQueueCreateSet( 1 * 2 );

    /* 将两个队列加入队列集。 */
    xQueueAddToSet( xQueue1, xQueueSet );
    xQueueAddToSet( xQueue2, xQueueSet );

    /* 创建向队列发送数据的任务。 */
    xTaskCreate( vSenderTask1, "Sender1", 1000, NULL, 1, NULL );
    xTaskCreate( vSenderTask2, "Sender2", 1000, NULL, 1, NULL );

    /* 创建读取队列集的任务，用于确定两个队列中的哪一个包含数据。 */
    xTaskCreate( vReceiverTask, "Receiver", 1000, NULL, 2, NULL );

    /* 启动调度器，使已创建的任务开始执行。 */
    vTaskStartScheduler();

    /* 正常情况下 vTaskStartScheduler() 不会返回，因此下面的代码永远
       不会执行。 */
    for( ;; );
    return 0;
}
```
***代码清单 5.24*** *示例 5.3 中 `main()` 的实现*

第一个发送任务每 100 毫秒通过 `xQueue1` 向接收任务发送一个字符指针；第二个发送任务每 200 毫秒通过 `xQueue2` 发送一个字符指针。这些字符指针指向用于标识发送任务的字符串。代码清单 5.25 给出了两个发送任务的实现。

<a name="list5.25" title="代码清单 5.25 示例 5.3 使用的发送任务"></a>

```c
{
    const TickType_t xBlockTime = pdMS_TO_TICKS( 100 );
    const char * const pcMessage = "Message from vSenderTask1\r\n";

    /* 与大多数任务一样，本任务在无限循环中实现。 */

    for( ;; )
    {

        /* 阻塞 100 毫秒。 */
        vTaskDelay( xBlockTime );

        /* 将本任务的字符串发送到 xQueue1。尽管队列只能容纳一个数据项，
           这里也无须使用阻塞时间。这是因为读取队列的任务优先级高于
           本任务；本任务一向队列写入数据，就会被读取队列的任务抢占，
           因此等 xQueueSend() 返回时，队列已经再次变为空。阻塞时间设为 0。 */
        xQueueSend( xQueue1, &pcMessage, 0 );
    }
}
```

***代码清单 5.25*** *示例 5.3 使用的发送任务*

两个发送任务写入的队列属于同一个队列集。每当任务向其中一个队列发送数据时，该队列的句柄都会被发送到队列集。接收任务调用 `xQueueSelectFromSet()` 从队列集读取队列句柄。收到句柄后，接收任务便知道该句柄所引用的队列中包含数据，因此直接读取对应队列。读取到的数据是指向字符串的指针，接收任务会将该字符串打印出来。

如果 `xQueueSelectFromSet()` 调用超时，它将返回 `NULL`。示例 5.3 使用无限阻塞时间调用 `xQueueSelectFromSet()`，因此该调用永远不会超时，只会返回有效的队列句柄。接收任务在使用返回值之前无须检查它是否为 `NULL`。

`xQueueSelectFromSet()` 只会在句柄所引用的队列中包含数据时返回该句柄，因此随后读取队列时无须使用阻塞时间。

代码清单 5.26 给出了接收任务的实现。

<a name="list5.26" title="代码清单 5.26 示例 5.3 使用的接收任务"></a>

```c
void vReceiverTask( void *pvParameters )
{
    QueueHandle_t xQueueThatContainsData;
    char *pcReceivedString;

    /* 与大多数任务一样，本任务在无限循环中实现。 */
    for( ;; )
    {
        /* 在队列集上阻塞，等待其中某个队列包含数据。已知队列集的所有
           成员都是队列（其中不含信号量），因此将 xQueueSelectFromSet()
           返回的 QueueSetMemberHandle_t 值强制转换为 QueueHandle_t。 */
        xQueueThatContainsData = ( QueueHandle_t ) xQueueSelectFromSet(
                                                     xQueueSet, portMAX_DELAY );

        /* 读取队列集时使用了无限阻塞时间，因此只有当队列集中的某个队列
           包含数据时 xQueueSelectFromSet() 才会返回，xQueueThatContainsData
           不可能为 NULL。读取该队列。由于已知队列中包含数据，无须指定
           阻塞时间，因此将其设为 0。 */
        xQueueReceive( xQueueThatContainsData, &pcReceivedString, 0 );

        /* 打印从队列接收到的字符串。 */
        vPrintString( pcReceivedString );
    }
}
```

### 5.6.5 更贴近实际的队列集用例

示例 5.3 展示的是一个非常简单的用例：队列集中只包含队列，而且两个队列都用于发送字符指针。在实际应用中，队列集可能同时包含队列和信号量，各个队列保存的数据类型也可能不同。此时，必须先检查 `xQueueSelectFromSet()` 的返回值，再决定如何使用它。代码清单 5.27 演示了如何处理包含以下成员的队列集：

- 一个二值信号量。
- 一个从中读取字符指针的队列。
- 一个从中读取`uint32_t`值的队列。

代码清单 5.27 假定这些队列和信号量均已创建并添加到队列集中。

<a name="list5.27" title="代码清单 5.27 使用同时包含队列和信号量的队列集"></a>

```c
QueueSetHandle_t xQueueSet;

    char *pcReceivedString;

           超时；否则返回值就是队列集中某个成员的句柄。

        if( xHandle == NULL )
        {
            /* xQueueSelectFromSet() 调用超时。 */
        }
        else if( xHandle == ( QueueSetMemberHandle_t ) xCharPointerQueue )
        {
            /* xQueueSelectFromSet() 返回了接收字符指针的队列句柄。读取该
               队列。已知队列中包含数据，因此阻塞时间设为 0。 */
            xQueueReceive( xCharPointerQueue, &pcReceivedString, 0 );

            /* 可在此处处理接收到的字符指针…… */
        }
        else if( xHandle == ( QueueSetMemberHandle_t ) xUint32tQueue )
        {

            xSemaphoreTake( xBinarySemaphore, 0 );

        }
```

<a id="57-using-a-queue-to-create-a-mailbox"></a>
## 5.7 使用队列创建邮箱

嵌入式系统领域尚未就相关术语达成共识，“邮箱”在不同 RTOS 中的含义也不尽相同。本书使用“邮箱”一词指代长度为 1 的队列。之所以把某个队列称为邮箱，是因为应用程序使用它的方式，而不是因为它在功能上与队列有所不同：

- 队列用于把数据从一个任务发送到另一个任务，或者从中断服务程序发送到任务。发送方把数据项放入队列，接收方再将该数据项从队列中移除。数据通过队列从发送方传递到接收方。

- 邮箱用于保存任何任务或中断服务程序都可以读取的数据。数据不会经由邮箱传递，而是一直保留在邮箱中，直到被覆盖。发送方覆盖邮箱中的值；接收方读取该值，但不会将其从邮箱中移除。

本章介绍两个可使队列充当邮箱的队列 API 函数。

代码清单 5.28 展示了如何创建一个用作邮箱的队列。

<a name="list5.28" title="代码清单 5.28 创建用作邮箱的队列"></a>

```c
/* 邮箱可保存一个固定大小的数据项。创建邮箱（队列）时会设定该数据项的
   大小。本例创建的邮箱用于保存 Example_t 结构体。Example_t 中包含一个
   时间戳，使邮箱中的数据能够记录邮箱上次更新的时间。本例使用时间戳
   只是为了演示；邮箱可以保存应用程序开发者需要的任意数据，其中无须
   包含时间戳。 */
typedef struct xExampleStructure
{
    TickType_t xTimeStamp;
    uint32_t ulValue;
} Example_t;

/* 邮箱就是队列，因此其句柄保存在 QueueHandle_t 类型的变量中。 */
QueueHandle_t xMailbox;

void vAFunction( void )
{
    /* 创建将用作邮箱的队列。队列长度为 1，以便配合下面介绍的
       xQueueOverwrite() API 函数使用。 */
    xMailbox = xQueueCreate( 1, sizeof( Example_t ) );
}
```

### 5.7.1 xQueueOverwrite() API 函数

与 `xQueueSendToBack()` 类似，`xQueueOverwrite()` API 函数也把数据发送到队列。不同之处在于，如果队列已满，`xQueueOverwrite()` 会覆盖队列中已有的数据。

`xQueueOverwrite()` 只能用于长度为 1 的队列。在覆盖模式下，函数始终写入队列头部并更新队列头指针，但不会增加待接收消息数。如果定义了 `configASSERT`，对长度大于 1 的队列调用该函数将触发断言。

> *注意：切勿从中断服务程序中调用 `xQueueOverwrite()`，应改用其中断安全版本 `xQueueOverwriteFromISR()`。*

<a name="list5.29" title="代码清单 5.29 xQueueOverwrite() API 函数原型"></a>

```c
BaseType_t xQueueOverwrite( QueueHandle_t xQueue, const void * pvItemToQueue );
```
***代码清单 5.29*** *`xQueueOverwrite()` API 函数原型*

**xQueueOverwrite() 参数和返回值**

- `xQueue`

  数据将被发送（写入）到的队列句柄。该句柄由创建队列时调用的 `xQueueCreate()` 或 `xQueueCreateStatic()` 返回。

- `pvItemToQueue`

  指向要复制到队列中的数据的指针。

  创建队列时已经设定每个数据项的大小，因此函数会从 `pvItemToQueue` 指向的位置向队列存储区复制相应数量的字节。

- 返回值

  即使队列已满，`xQueueOverwrite()` 也会成功写入，因此唯一可能的返回值是 `pdPASS`。

代码清单 5.30 展示了如何使用 `xQueueOverwrite()` 写入代码清单 5.28 创建的邮箱（队列）。

<a name="list5.30" title="代码清单 5.30 使用 xQueueOverwrite() API 函数"></a>

```c
void vUpdateMailbox( uint32_t ulNewValue )
{
    /* Example_t 已在代码清单 5.28 中定义。 */
    Example_t xData;

    /* 将新数据写入 Example_t 结构体。 */
    xData.ulValue = ulNewValue;

    /* 使用 RTOS Tick 计数作为 Example_t 结构体中保存的时间戳。 */
    xData.xTimeStamp = xTaskGetTickCount();

    /* 将结构体发送到邮箱，覆盖其中已有的数据。 */
    xQueueOverwrite( xMailbox, &xData );
}
```

### 5.7.2 xQueuePeek() API 函数

`xQueuePeek()` 从队列接收（读取）一个数据项，*但不会*将该数据项从队列中移除。它读取队列头部的数据，却不会修改队列中保存的数据，也不会改变数据在队列中的存储顺序。

> *注意：切勿从中断服务程序中调用 `xQueuePeek()`，应改用其中断安全版本 `xQueuePeekFromISR()`。*

*`xQueuePeek()` 的函数参数和返回值与 `xQueueReceive()` 相同。*

<a name="list5.31" title="代码清单 5.31 xQueuePeek() API 函数原型"></a>

```c
BaseType_t xQueuePeek( QueueHandle_t xQueue,
                       void * const pvBuffer,
                       TickType_t xTicksToWait );
```

代码清单 5.32 展示了如何使用 `xQueuePeek()` 接收代码清单 5.30 发布到邮箱（队列）的数据项。

<a name="list5.32" title="代码清单 5.32 使用 xQueuePeek() API 函数"></a>

```c
BaseType_t vReadMailbox( Example_t *pxData )
{
    TickType_t xPreviousTimeStamp;
    BaseType_t xDataUpdated;

    /* 本函数使用从邮箱读取到的最新值更新 Example_t 结构体。在 *pxData
       被新数据覆盖之前，先记录其中原有的时间戳。 */
    xPreviousTimeStamp = pxData->xTimeStamp;

    /* 使用邮箱中的数据更新 pxData 所指向的 Example_t 结构体。如果这里
       使用 xQueueReceive()，邮箱会被读空，其他任务便无法再读取其中的
       数据。使用 xQueuePeek() 代替 xQueueReceive() 可确保数据仍留在邮箱中。

       这里指定了阻塞时间；如果邮箱为空，调用任务将进入阻塞状态等待
       邮箱中出现数据。由于使用无限阻塞时间，无须检查 xQueuePeek() 的
       返回值，因为只有在数据可用时 xQueuePeek() 才会返回。 */
    xQueuePeek( xMailbox, pxData, portMAX_DELAY );

    /* 如果邮箱中的值自上次调用本函数后已更新，则返回 pdTRUE；否则返回
       pdFALSE。 */
    if( pxData->xTimeStamp > xPreviousTimeStamp )
    {
        xDataUpdated = pdTRUE;
    }
    else
    {
        xDataUpdated = pdFALSE;
    }

    return xDataUpdated;
}
```
