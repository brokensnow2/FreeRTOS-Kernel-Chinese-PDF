# 11 低功耗支持

<a id="111-power-saving-introduction"></a>
## 11.1 省电简介

FreeRTOS 提供了一种简单的方式，通过空闲任务钩子和无滴答空闲模式来利用低功耗模式。

通常通过使用空闲任务钩子将微控制器置于低功耗状态来降低运行 FreeRTOS 的微控制器的功耗。这种方法所能实现的节能效果受到以下因素的限制：必须定期退出然后重新进入低功耗状态以处理滴答中断。此外，如果滴答中断的频率过高（从空闲状态唤醒过于频繁），那么每个滴答进出低功耗状态所消耗的能量和时间将抵消除最浅的省电模式之外的任何潜在节能收益。

FreeRTOS 支持一种低功耗状态，允许微控制器定期进入和退出低功耗状态。FreeRTOS 无滴答空闲模式在空闲期间（当没有应用程序任务可以执行时）停止周期性滴答中断，这使得 MCU 能够保持在深度省电状态，直到发生中断，或者直到 RTOS 内核需要将任务转换到就绪状态。然后在重新启动滴答中断时对 RTOS 滴答计数值进行修正调整。FreeRTOS 无滴答模式的原理是当 MCU 执行空闲任务时，使其进入低功耗模式以节省系统功耗。

<a id="112-freertos-sleep-modes"></a>
## 11.2 FreeRTOS 睡眠模式

FreeRTOS 支持三种类型的睡眠模式：

1. eAbortSleep - 此模式表示某个任务已就绪、已挂起上下文切换，或者滴答中断已发生但因调度器被挂起而暂时挂起。它通知 RTOS 中止进入睡眠模式。

2. eStandardSleep - 此模式允许进入一个不会超过预期空闲时间的睡眠模式。

3. eNoTasksWaitingTimeout - 当没有任务在等待超时时进入此模式，因此可以安全地进入只能通过外部中断或复位退出的睡眠模式。

<a id="113-functions-and-enabling-built-in-tickless-idle-functionality"></a>
## 11.3 函数及内置无滴答空闲功能启用

内置无滴答空闲功能通过在 FreeRTOSConfig.h 中将 `configUSE_TICKLESS_IDLE` 定义为 1 来启用（适用于支持此功能的端口）。用户定义的无滴答空闲功能可以通过在 FreeRTOSConfig.h 中将 `configUSE_TICKLESS_IDLE` 定义为 2 来为任何 FreeRTOS 端口（包括包含内置实现的端口）提供。

当无滴答空闲功能启用时，内核将在满足以下两个条件时调用 `portSUPPRESS_TICKS_AND_SLEEP()` 宏：

1. 空闲任务是唯一能够运行的任务，因为所有应用程序任务都处于阻塞态或挂起态。

2. 在内核需要将应用程序任务从阻塞态转换出来之前，至少还会经过 n 个完整的滴答周期，其中 n 由 FreeRTOSConfig.h 中的 `configEXPECTED_IDLE_TIME_BEFORE_SLEEP` 定义设置。

### 11.3.3 eTaskConfirmSleepModeStatus 函数

API *eTaskConfirmSleepModeStatus* 返回睡眠模式状态，以确定是否可以继续进行睡眠，以及是否可以无限期睡眠。此功能仅在 `configUSE_TICKLESS_IDLE` 设置为 1 时可用。

<a name="list11.3" title="Listing 11.3 The eTaskConfirmSleepModeStatus API function prototype"></a>

```c
eSleepModeStatus eTaskConfirmSleepModeStatus( void );
```
***清单 11.3*** *eTaskConfirmSleepModeStatus API 函数原型*

如果在 `portSUPPRESS_TICKS_AND_SLEEP()` 内部调用 `eTaskConfirmSleepModeStatus()` 返回 `eNoTasksWaitingTimeout`，则微控制器可以无限期地保持在深度睡眠状态。仅当以下条件为真时，`eTaskConfirmSleepModeStatus()` 才会返回 `eNoTasksWaitingTimeout`：

+ 未使用软件定时器，因此调度器不会在未来的任何时间执行定时器回调函数。

+ 所有应用程序任务要么处于挂起态，要么处于超时值为 `portMAX_DELAY` 的阻塞态，因此调度器不会在未来的任何固定时间将任务从阻塞态转换出来。

为避免竞态条件，FreeRTOS 调度器在调用 `portSUPPRESS_TICKS_AND_SLEEP()` 之前被挂起，并在 `portSUPPRESS_TICKS_AND_SLEEP()` 完成时恢复。这确保在微控制器退出低功耗状态与 `portSUPPRESS_TICKS_AND_SLEEP()` 完成执行之间，应用程序任务无法执行。此外，`portSUPPRESS_TICKS_AND_SLEEP()` 函数必须在定时器停止和进入睡眠模式之间创建一个小型临界区，以确保继续进入睡眠模式是安全的。应在此临界区内调用 `eTaskConfirmSleepModeStatus()`。

此外，FreeRTOS 为用户提供了两个在 FreeRTOSConfig.h 中定义的其他接口函数。这些宏允许应用程序编写者分别在 MCU 进入低功耗状态之前和之后添加额外的步骤。

## 11.4 实现 portSUPPRESS\_TICKS\_AND\_SLEEP() 宏

如果使用的 FreeRTOS 端口没有提供 `portSUPPRESS_TICKS_AND_SLEEP()` 的默认实现，那么应用程序编写者可以通过在 FreeRTOSConfig.h 中定义 `portSUPPRESS_TICKS_AND_SLEEP()` 来提供自己的实现。如果使用的 FreeRTOS 端口确实提供了 `portSUPPRESS_TICKS_AND_SLEEP()` 的默认实现，那么应用程序编写者可以通过在 FreeRTOSConfig.h 中定义 `portSUPPRESS_TICKS_AND_SLEEP()` 来覆盖默认实现。

以下源代码是应用程序编写者如何实现 `portSUPPRESS_TICKS_AND_SLEEP()` 的示例。该示例是基础的，并且会在内核维护的时间和日历时间之间引入一些偏差。在示例中显示的函数调用中，只有 `vTaskStepTick()` 和 `eTaskConfirmSleepModeStatus()` 是 FreeRTOS API 的一部分。其他函数特定于所用硬件上可用的时钟和省电模式，因此必须由应用程序编写者提供。

<a name="list11.6" title="Listing 11.6 An example of a user defined implementation of portSUPPRESS\_TICKS\_AND\_SLEEP()"></a>

```c
/* First define the portSUPPRESS_TICKS_AND_SLEEP() macro.  The parameter is the
   time, in ticks, until the kernel next needs to execute. */

#define portSUPPRESS_TICKS_AND_SLEEP( xIdleTime ) vApplicationSleep( xIdleTime )

/* Define the function that is called by portSUPPRESS_TICKS_AND_SLEEP(). */
void vApplicationSleep( TickType_t xExpectedIdleTime )
{
    unsigned long ulLowPowerTimeBeforeSleep, ulLowPowerTimeAfterSleep;

    eSleepModeStatus eSleepStatus;

    /* Read the current time from a time source that will remain operational
       while the microcontroller is in a low power state. */
    ulLowPowerTimeBeforeSleep = ulGetExternalTime();

    /* Stop the timer that is generating the tick interrupt. */
    prvStopTickInterruptTimer();

    /* Enter a critical section that will not effect interrupts bringing the MCU
       out of sleep mode. */
    disable_interrupts();

    /* Ensure it is still ok to enter the sleep mode. */
    eSleepStatus = eTaskConfirmSleepModeStatus();

    if( eSleepStatus == eAbortSleep )
    {
        /* A task has been moved out of the Blocked state since this macro was
           executed, or a context siwth is being held pending.  Do not enter a
           sleep state.  Restart the tick and exit the critical section. */
        prvStartTickInterruptTimer();
        enable_interrupts();
    }
    else
    {
        if( eSleepStatus == eNoTasksWaitingTimeout )
        {
            /* It is not necessary to configure an interrupt to bring the
               microcontroller out of its low power state at a fixed time in 
               the future. */
            prvSleep();
        }
        else
        {
            /* Configure an interrupt to bring the microcontroller out of its low
               power state at the time the kernel next needs to execute.  The
               interrupt must be generated from a source that remains operational
               when the microcontroller is in a low power state. */
            vSetWakeTimeInterrupt( xExpectedIdleTime );

            /* Enter the low power state. */
            prvSleep();

            /* Determine how long the microcontroller was actually in a low power
               state for, which will be less than xExpectedIdleTime if the
               microcontroller was brought out of low power mode by an interrupt
               other than that configured by the vSetWakeTimeInterrupt() call.
               Note that the scheduler is suspended before
               portSUPPRESS_TICKS_AND_SLEEP() is called, and resumed when
               portSUPPRESS_TICKS_AND_SLEEP() returns.  Therefore no other tasks will
               execute until this function completes. */
            ulLowPowerTimeAfterSleep = ulGetExternalTime();

            /* Correct the kernels tick count to account for the time the
               microcontroller spent in its low power state. */
            vTaskStepTick( ulLowPowerTimeAfterSleep - ulLowPowerTimeBeforeSleep );
        }

        /* Exit the critical section - it might be possible to do this immediately
           after the prvSleep() calls. */
        enable_interrupts();

        /* Restart the timer that is generating the tick interrupt. */
        prvStartTickInterruptTimer();
    }
}
```
***清单 11.6*** *用户自定义 portSUPPRESS\_TICKS\_AND\_SLEEP() 实现的示例*

## 11.5 空闲任务钩子函数

空闲任务可以选择调用应用程序定义的钩子（或回调）函数——即空闲钩子。空闲任务以最低优先级运行，因此只有在没有更高优先级的任务可以运行时，才会执行空闲钩子函数。这使得空闲钩子函数成为将处理器置于低功耗状态的理想位置——在没有处理任务时提供自动省电功能。只有在 FreeRTOSConfig.h 中将 `configUSE_IDLE_HOOK` 设置为 1 时，才会调用空闲钩子。

<a name="list11.7" title="Listing 11.7 The vApplicationIdleHook API function prototype"></a>

```c
void vApplicationIdleHook( void );
```
***清单 11.7*** *vApplicationIdleHook API 函数原型*

只要空闲任务正在运行，就会重复调用空闲钩子。至关重要的是，空闲钩子函数不能调用任何可能导致其阻塞的 API 函数。此外，如果应用程序使用了 `vTaskDelete()` API 函数，则必须允许空闲任务钩子定期返回，因为空闲任务负责清理 RTOS 内核为已删除任务分配的资源。
