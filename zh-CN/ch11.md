# 11 低功耗支持

<a id="111-power-saving-introduction"></a>
## 11.1 节能简介

FreeRTOS 提供了两种简单的低功耗机制：空闲任务钩子和无 Tick 空闲模式。

一种常见的降低功耗方法，是在空闲任务钩子中让运行 FreeRTOS 的微控制器进入低功耗状态。不过，这种方法的节能效果受到限制，因为系统必须周期性退出低功耗状态以处理 Tick 中断，然后再次进入低功耗状态。此外，如果 Tick 中断频率过高，也就是系统过于频繁地从空闲状态唤醒，那么除非使用最浅的节能模式，否则每个 Tick 进入和退出低功耗状态所消耗的能量与时间，可能超过节省的能量。

FreeRTOS 支持让微控制器周期性进入和退出低功耗状态。FreeRTOS 的无 Tick 空闲模式会在空闲期间停止周期性 Tick 中断；所谓空闲期间，是指没有任何应用任务能够执行的时段。这样，MCU 可以一直保持深度节能状态，直到发生中断，或者 RTOS 内核需要把某个任务转入就绪状态。重新启动 Tick 中断时，内核会相应校正 RTOS Tick 计数值。FreeRTOS 无 Tick 模式的基本原理是：当 MCU 正在执行空闲任务时，让它进入低功耗模式，从而降低系统功耗。

<a id="112-freertos-sleep-modes"></a>
## 11.2 FreeRTOS 睡眠模式

FreeRTOS 支持三种睡眠模式状态：

1. `eAbortSleep`：表示某个任务已进入就绪状态、上下文切换正等待执行，或者调度器挂起期间已经发生了 Tick 中断且该中断正等待处理。该状态通知 RTOS 放弃进入睡眠模式。

2. `eStandardSleep`：允许系统进入睡眠模式，但睡眠时间不会超过预计的空闲时间。

3. `eNoTasksWaitingTimeout`：没有任何任务正在等待超时，因此可以安全进入只能由外部中断或复位退出的睡眠模式。

<a id="113-functions-and-enabling-built-in-tickless-idle-functionality"></a>
## 11.3 启用内置无 Tick 空闲功能及相关函数

对于支持该功能的移植版本，在 FreeRTOSConfig.h 中把 `configUSE_TICKLESS_IDLE` 定义为 1，即可启用内置无 Tick 空闲功能。对于任何 FreeRTOS 移植版本，包括已经内置相关实现的版本，都可以在 FreeRTOSConfig.h 中把 `configUSE_TICKLESS_IDLE` 定义为 2，以提供用户自定义的无 Tick 空闲功能。

启用无 Tick 空闲功能后，内核会在同时满足以下两个条件时调用 `portSUPPRESS_TICKS_AND_SLEEP()` 宏：

1. 空闲任务是唯一能够运行的任务，因为所有应用任务都处于阻塞状态或挂起状态。

2. 在内核需要把某个应用任务移出阻塞状态之前，至少还会经过 n 个完整的 Tick 周期。n 由 FreeRTOSConfig.h 中的 `configEXPECTED_IDLE_TIME_BEFORE_SLEEP` 定义设置。

***代码清单 11.1*** *`portSUPPRESS_TICKS_AND_SLEEP` 宏的原型*

`portSUPPRESS_TICKS_AND_SLEEP()` 的 `xExpectedIdleTime` 参数值，等于下一个任务应被转入就绪状态之前的 Tick 周期总数。因此，该参数表示在抑制 Tick 中断的情况下，微控制器能够安全保持深度睡眠状态的时间。

<a id="1133-the-etaskconfirmsleepmodestatus-function"></a>
### 11.3.3 eTaskConfirmSleepModeStatus 函数

`eTaskConfirmSleepModeStatus()` API 函数返回睡眠模式状态，用于判断是否可以继续进入睡眠，以及是否可以无限期休眠。只有把 `configUSE_TICKLESS_IDLE` 设为 1 时，才能使用此功能。

<a name="list11.3" title="代码清单 11.3 eTaskConfirmSleepModeStatus API 函数原型"></a>

```c
eSleepModeStatus eTaskConfirmSleepModeStatus( void );
```

***代码清单 11.3*** *`eTaskConfirmSleepModeStatus` API 函数原型*

如果在 `portSUPPRESS_TICKS_AND_SLEEP()` 内部调用 `eTaskConfirmSleepModeStatus()` 时返回 `eNoTasksWaitingTimeout`，那么微控制器可以无限期保持深度睡眠状态。只有同时满足以下条件时，`eTaskConfirmSleepModeStatus()` 才会返回 `eNoTasksWaitingTimeout`：

- 没有使用软件定时器，因此调度器以后任何时候都不需要执行定时器回调函数。

- 所有应用任务都处于挂起状态，或者处于阻塞状态且超时值为 `portMAX_DELAY`，因此调度器以后不需要在任何固定时刻把任务移出阻塞状态。

为避免竞争条件，FreeRTOS 会在调用 `portSUPPRESS_TICKS_AND_SLEEP()` 之前挂起调度器，并在 `portSUPPRESS_TICKS_AND_SLEEP()` 执行完毕后恢复调度器。这样可以确保微控制器退出低功耗状态之后、`portSUPPRESS_TICKS_AND_SLEEP()` 完成执行之前，应用任务无法运行。此外，`portSUPPRESS_TICKS_AND_SLEEP()` 函数必须在停止定时器与进入睡眠模式之间建立一个短临界区，以确认此时仍可继续进入睡眠模式。应当在这个临界区内调用 `eTaskConfirmSleepModeStatus()`。

此外，FreeRTOS 还向用户提供了另外两个在 FreeRTOSConfig.h 中定义的接口宏。应用程序开发者可以通过它们，分别在 MCU 进入低功耗状态之前和退出低功耗状态之后添加额外处理步骤。

<a id="114-implementing-portsuppressticksandsleep-macro"></a>
## 11.4 实现 portSUPPRESS\_TICKS\_AND\_SLEEP() 宏

如果所用的 FreeRTOS 移植版本没有提供 `portSUPPRESS_TICKS_AND_SLEEP()` 的默认实现，应用程序开发者可以在 FreeRTOSConfig.h 中定义 `portSUPPRESS_TICKS_AND_SLEEP()`，提供自己的实现。如果所用的 FreeRTOS 移植版本已经提供 `portSUPPRESS_TICKS_AND_SLEEP()` 的默认实现，应用程序开发者同样可以在 FreeRTOSConfig.h 中定义 `portSUPPRESS_TICKS_AND_SLEEP()`，覆盖默认实现。

下面的源代码演示应用程序开发者可以如何实现 `portSUPPRESS_TICKS_AND_SLEEP()`。这个示例比较基础，会使内核维护的时间与日历时间之间产生少量偏差。在示例调用的函数中，只有 `vTaskStepTick()` 和 `eTaskConfirmSleepModeStatus()` 属于 FreeRTOS API。其他函数取决于所用硬件提供的时钟和节能模式，必须由应用程序开发者实现。

<a name="list11.6" title="代码清单 11.6 用户自定义 portSUPPRESS_TICKS_AND_SLEEP() 实现示例"></a>

```c
/* 首先定义 portSUPPRESS_TICKS_AND_SLEEP() 宏。参数表示距内核下次需要执行
   还有多少个 Tick。 */

#define portSUPPRESS_TICKS_AND_SLEEP( xIdleTime ) vApplicationSleep( xIdleTime )

/* 定义由 portSUPPRESS_TICKS_AND_SLEEP() 调用的函数。 */
void vApplicationSleep( TickType_t xExpectedIdleTime )
{
    unsigned long ulLowPowerTimeBeforeSleep, ulLowPowerTimeAfterSleep;

    eSleepModeStatus eSleepStatus;

    /* 从一个在微控制器处于低功耗状态时仍会运行的时钟源读取当前时间。 */
    ulLowPowerTimeBeforeSleep = ulGetExternalTime();

    /* 停止生成 Tick 中断的定时器。 */
    prvStopTickInterruptTimer();

    /* 进入一个不会影响 MCU 睡眠唤醒中断的临界区。 */
    disable_interrupts();

    /* 确认此时仍可进入睡眠模式。 */
    eSleepStatus = eTaskConfirmSleepModeStatus();

    if( eSleepStatus == eAbortSleep )
    {
        /* 自本宏执行以来，已有任务移出阻塞状态，或者有上下文切换正等待执行。
           不要进入睡眠状态。重新启动 Tick，并退出临界区。 */
        prvStartTickInterruptTimer();
        enable_interrupts();
    }
    else
    {
        if( eSleepStatus == eNoTasksWaitingTimeout )
        {
            /* 无需配置一个在未来固定时刻将微控制器从低功耗状态唤醒的中断。 */
            prvSleep();
        }
        else
        {
            /* 配置一个中断，在内核下次需要执行时将微控制器从低功耗状态唤醒。
               该中断必须由微控制器处于低功耗状态时仍能运行的中断源生成。 */
            vSetWakeTimeInterrupt( xExpectedIdleTime );

            /* 进入低功耗状态。 */
            prvSleep();

            /* 确定微控制器实际处于低功耗状态的时长。如果唤醒微控制器的是
               vSetWakeTimeInterrupt() 配置之外的其他中断，该值会小于
               xExpectedIdleTime。注意，调用 portSUPPRESS_TICKS_AND_SLEEP() 之前
               调度器已经挂起，并会在 portSUPPRESS_TICKS_AND_SLEEP() 返回时恢复。
               因此，在本函数执行完毕之前，不会有其他任务运行。 */
            ulLowPowerTimeAfterSleep = ulGetExternalTime();

            /* 校正内核的 Tick 计数，以计入微控制器处于低功耗状态的时间。 */
            vTaskStepTick( ulLowPowerTimeAfterSleep - ulLowPowerTimeBeforeSleep );
        }

        /* 退出临界区。也可以考虑紧接在 prvSleep() 调用之后执行此操作。 */
        enable_interrupts();

        /* 重新启动生成 Tick 中断的定时器。 */
        prvStartTickInterruptTimer();
    }
}
```

***代码清单 11.6*** *用户自定义 `portSUPPRESS_TICKS_AND_SLEEP()` 实现示例*

<a id="115-idle-task-hook-function"></a>
## 11.5 空闲任务钩子函数

空闲任务可以选择调用由应用程序定义的钩子函数或回调函数，即空闲钩子。空闲任务以最低优先级运行，因此只有在没有更高优先级任务能够运行时，空闲钩子函数才会执行。这使空闲钩子函数非常适合用于让处理器进入低功耗状态，在没有工作需要处理时自动节能。只有在 FreeRTOSConfig.h 中把 `configUSE_IDLE_HOOK` 设为 1，系统才会调用空闲钩子。

<a name="list11.7" title="代码清单 11.7 vApplicationIdleHook API 函数原型"></a>

```c
void vApplicationIdleHook( void );
```

***代码清单 11.7*** *`vApplicationIdleHook` API 函数原型*

只要空闲任务持续运行，就会反复调用空闲钩子。最重要的是，空闲钩子函数绝不能调用任何可能使其阻塞的 API 函数。此外，如果应用程序使用 `vTaskDelete()` API 函数，空闲任务钩子就必须能够周期性返回，因为空闲任务负责清理由 RTOS 内核为已删除任务分配的资源。
