# 6 软件定时器管理

<a id="61-chapter-introduction-and-scope"></a>
## 6.1 本章简介与范围

软件定时器用于安排函数在未来某个设定时刻执行，或以固定频率周期性执行。由软件定时器执行的函数称为软件定时器回调函数。

软件定时器由 FreeRTOS 内核实现和控制，不需要硬件支持，也与硬件定时器或硬件计数器无关。

FreeRTOS 采用经过精心设计的实现来确保高效率：除执行软件定时器回调函数之外，软件定时器不会占用任何处理时间。

软件定时器功能是可选的。要启用该功能，需要：

1. 将 FreeRTOS 源文件 `FreeRTOS/Source/timers.c` 加入项目并参与编译。

2. 在应用程序的 `FreeRTOSConfig.h` 头文件中定义以下配置常量：

- `configUSE_TIMERS`

  在 `FreeRTOSConfig.h` 中将 `configUSE_TIMERS` 设为 1。

- `configTIMER_TASK_PRIORITY`

  设置定时器服务任务的优先级，取值范围为 0 到 `configMAX_PRIORITIES - 1`。

- `configTIMER_QUEUE_LENGTH`

  设置定时器命令队列在任意时刻最多能够容纳的待处理命令数。

- `configTIMER_TASK_STACK_DEPTH`

  设置分配给定时器服务任务的栈大小，单位为字而不是字节。

### 6.1.1 范围

## 6.2 软件定时器回调函数

软件定时器回调函数以 C 函数实现。它唯一的特殊之处在于函数原型：返回类型必须是 `void`，并且唯一参数必须是软件定时器句柄。代码清单 6.1 给出了回调函数原型。

<a name="list6.1" title="代码清单 6.1 软件定时器回调函数原型"></a>

```c
void ATimerCallback( TimerHandle_t xTimer );
```
***代码清单 6.1*** *软件定时器回调函数原型*

软件定时器回调函数会从头到尾执行并正常返回。回调函数应当尽量简短，而且绝不能进入阻塞状态。

> *注意：后文将说明，软件定时器回调函数在 FreeRTOS 调度器启动时自动创建的任务上下文中执行。因此，回调函数绝不能调用会使调用任务进入阻塞状态的 FreeRTOS API 函数。可以调用 `xQueueReceive()` 之类的函数，但必须把指定阻塞时间的 `xTicksToWait` 参数设为 0。不能调用 `vTaskDelay()` 之类的函数，因为 `vTaskDelay()` 总会使调用任务进入阻塞状态。*

## 6.3 软件定时器的属性和状态

<a id="631-period-of-a-software-timer"></a>
### 6.3.1 软件定时器的周期

软件定时器的“周期”是从软件定时器启动到其回调函数执行之间的时间间隔。

<a id="632-one-shot-and-auto-reload-timers"></a>
### 6.3.2 单次定时器与自动重载定时器

有两种类型的软件定时器：

1. 单次定时器

   启动后，单次定时器只执行一次回调函数。它可以手动重新启动，但不会自行重新启动。

1. 自动重载定时器

   启动后，自动重载定时器每次到期都会自行重新启动，因此其回调函数会周期性执行。

### 6.3.3 软件定时器状态

软件定时器可以处于以下两种状态之一：

- 休眠状态

  处于休眠状态的软件定时器仍然存在，也可以通过句柄引用，但它并未运行，因此不会执行回调函数。

- 运行状态

  软件定时器进入运行状态或上次复位后，经过一个完整周期便会执行回调函数。

***代码清单 6.2*** *`xTimerDelete()` API 函数原型*

**xTimerDelete() 参数和返回值**

- `xTimer`

  要删除的定时器句柄。

- `xTicksToWait`

  调用 `xTimerDelete()` 时，如果定时器命令队列已满，该参数指定调用任务为等待删除命令成功发送到队列而保持阻塞状态的最长时间，单位为 Tick。如果在调度器启动前调用 `xTimerDelete()`，则忽略 `xTicksToWait`。

- 返回值

  有两个可能的返回值：

  - `pdPASS`

    如果删除命令成功发送到定时器命令队列，则返回 `pdPASS`。

  - `pdFAIL`

    如果等待 `xTicksToWait` 个 Tick 后，删除命令仍无法发送到定时器命令队列，则返回 `pdFAIL`。

<a id="64-the-context-of-a-software-timer"></a>
## 6.4 软件定时器的上下文

<a id="641-the-rtos-daemon-timer-service-task"></a>
### 6.4.1 RTOS 守护任务（定时器服务任务）

所有软件定时器回调函数都在同一个 RTOS 守护任务（也称“定时器服务任务”）的上下文中执行[^10]。

[^10]: 该任务以前称为“定时器服务任务”，因为最初只用于执行软件定时器回调函数。现在同一任务还承担其他用途，因此改用更通用的名称“RTOS 守护任务”。

守护任务是一个标准 FreeRTOS 任务，在调度器启动时自动创建。它的优先级和栈大小分别由编译时配置常量 `configTIMER_TASK_PRIORITY` 和 `configTIMER_TASK_STACK_DEPTH` 设置，这两个常量都在 `FreeRTOSConfig.h` 中定义。

软件定时器回调函数不得调用会使调用任务进入阻塞状态的 FreeRTOS API 函数，否则守护任务也会随之进入阻塞状态。

<a id="642-the-timer-command-queue"></a>
### 6.4.2 定时器命令队列

定时器命令队列是一个标准 FreeRTOS 队列，在调度器启动时自动创建。队列长度由 `FreeRTOSConfig.h` 中的编译时配置常量 `configTIMER_QUEUE_LENGTH` 设置。

* * *
![](media/image42.png)   
***图 6.5*** *调用 `xTimerStart()` 的任务优先级高于守护任务时的执行模式*

参照图 6.5，其中任务 1 的优先级高于守护任务，而守护任务的优先级又高于空闲任务：

1. 在时刻 t1

   任务 1 处于运行状态，守护任务处于阻塞状态。

   如果有命令发送到定时器命令队列，守护任务将退出阻塞状态并处理该命令；如果软件定时器到期，守护任务也会退出阻塞状态并执行相应的回调函数。

1. 在时刻 t2

   任务 1 调用 `xTimerStart()`。

   `xTimerStart()` 向定时器命令队列发送一条命令，使守护任务退出阻塞状态。由于任务 1 的优先级高于守护任务，守护任务不会抢占任务 1。

   任务 1 仍处于运行状态，守护任务则从阻塞状态转入就绪状态。

1. 在时刻 t3

   任务 1 完成 `xTimerStart()` API 函数的执行。从进入函数到函数返回，任务 1 始终处于运行状态。

1. 在时刻 t4

   任务 1 调用某个使其进入阻塞状态的 API 函数。此时守护任务是就绪任务中优先级最高的任务，因此调度器选择守护任务进入运行状态。随后，守护任务开始处理任务 1 发送到定时器命令队列的命令。

   > *注意：软件定时器的到期**时间**从“启动定时器”命令发送到定时器命令队列的时刻开始计算，而不是从守护任务读取并处理该命令的时刻开始计算。*

1. 在时刻 t5

   守护任务已处理完任务 1 发送的命令，并尝试从定时器命令队列接收更多数据。由于队列为空，守护任务重新进入阻塞状态。当有新命令发送到定时器命令队列，或某个软件定时器到期时，它会再次退出阻塞状态。

   此时空闲任务是就绪任务中优先级最高的任务，因此调度器选择空闲任务进入运行状态。

图 6.6 展示了与图 6.5 类似的场景，但这一次守护任务的优先级高于调用 `xTimerStart()` 的任务。

* * *
![](media/image43.png)   
***图 6.6*** *调用 `xTimerStart()` 的任务优先级低于守护任务时的执行模式*

参照图 6.6，其中守护任务的优先级高于任务 1，而任务 1 的优先级又高于空闲任务：

1. 在时刻 t1

   与前一种情况相同，任务 1 处于运行状态，守护任务处于阻塞状态。

1. 在时刻 t2

   任务 1 调用 `xTimerStart()`。

   `xTimerStart()` 向定时器命令队列发送一条命令，使守护任务退出阻塞状态。由于守护任务的优先级高于任务 1，调度器选择守护任务进入运行状态。

   任务 1 尚未执行完 `xTimerStart()` 就被守护任务抢占，因而转入就绪状态。

   守护任务开始处理任务 1 发送到定时器命令队列的命令。

1. 在时刻 t3

   守护任务处理完任务 1 发送的命令，并尝试从定时器命令队列接收更多数据。由于队列为空，守护任务重新进入阻塞状态。

   此时任务 1 是就绪任务中优先级最高的任务，因此调度器选择任务 1 再次进入运行状态。

1. 在时刻 t4

   任务 1 先前在 `xTimerStart()` 返回前被守护任务抢占，现在重新进入运行状态，并从 `xTimerStart()` 返回。

1. 在时刻 t5

   任务 1 调用某个使其进入阻塞状态的 API 函数。此时空闲任务成为就绪任务中优先级最高的任务，因此调度器选择空闲任务进入运行状态。

在图 6.5 所示的场景中，任务 1 把命令发送到定时器命令队列后，经过一段时间守护任务才读取并处理该命令。在图 6.6 所示的场景中，任务 1 甚至还没有从发送命令的函数返回，守护任务就已经读取并处理了命令。

发送到定时器命令队列的命令包含时间戳，用于计入应用程序任务发送命令到守护任务处理命令之间经过的时间。例如，若发送“启动定时器”命令来启动一个周期为 10 个 Tick 的定时器，时间戳可确保定时器在命令发出 10 个 Tick 后到期，而不是在守护任务处理命令 10 个 Tick 后才到期。

<a id="65-creating-and-starting-a-software-timer"></a>
## 6.5 创建和启动软件定时器

<a id="651-the-xtimercreate-api-function"></a>
### 6.5.1 xTimerCreate() API 函数

软件定时器必须先显式创建，才能使用。除了 `xTimerCreate()`，FreeRTOS 还提供 `xTimerCreateStatic()`，后者使用由应用程序在编译期静态分配的内存创建定时器。

软件定时器通过 `TimerHandle_t` 类型的变量引用。`xTimerCreate()` 用于创建软件定时器，并返回引用新定时器的 `TimerHandle_t`。软件定时器创建后处于休眠状态。

软件定时器既可以在调度器启动前创建，也可以在调度器启动后由任务创建。

[第 2.5 节“数据类型和编码风格指南”](ch02.md#25-data-types-and-coding-style-guide)介绍了这里使用的数据类型和命名约定。

<a name="list6.3" title="代码清单 6.3 xTimerCreate() API 函数原型"></a>

```c
TimerHandle_t xTimerCreate( const char * const pcTimerName,
                            const TickType_t xTimerPeriodInTicks,
                            const BaseType_t xAutoReload,
                            void * const pvTimerID,
                            TimerCallbackFunction_t pxCallbackFunction );
```
***代码清单 6.3*** *`xTimerCreate()` API 函数原型*

**xTimerCreate() 参数和返回值**

- `pcTimerName`

  定时器的描述性名称。FreeRTOS 本身不会使用该名称，它仅用于辅助调试。与句柄相比，便于阅读的名称更容易帮助开发者识别定时器。

- `xTimerPeriodInTicks`

  以 Tick 为单位的定时器周期。宏 `pdMS_TO_TICKS()` 可将毫秒转换为 Tick 数。该参数不能为 0。

- `xAutoReload`

  将 `xAutoReload` 设为 `pdTRUE` 可创建自动重载定时器，设为 `pdFALSE` 则创建单次定时器。

- `pvTimerID`

  每个软件定时器都有一个 ID 值。ID 的类型是 `void` 指针，应用程序开发者可以按需要使用它。当多个软件定时器共用同一个回调函数时，ID 尤其有用，因为它可以为每个定时器提供专属存储。本章后续示例会演示定时器 ID 的用法。

  `pvTimerID` 用于设置所创建定时器的初始 ID 值。

- `pxCallbackFunction`

  软件定时器回调函数是符合代码清单 6.1 所示原型的 C 函数。`pxCallbackFunction` 是指向回调函数的指针，实际使用时就是函数名，该函数将作为新定时器的回调函数。

- 返回值

  如果返回 `NULL`，则表示软件定时器创建失败，因为没有足够的堆内存供 FreeRTOS 分配所需的数据结构。

  如果返回值不是 `NULL`，则表示软件定时器创建成功，返回值就是新定时器的句柄。

  第 3 章提供了有关堆内存管理的更多信息。

<a id="652-the-xtimerstart-api-function"></a>
### 6.5.2 xTimerStart() API 函数

`xTimerStart()` 用于启动处于休眠状态的软件定时器，也可以复位（重新启动）处于运行状态的软件定时器。`xTimerStop()` 用于停止正在运行的软件定时器；停止定时器等同于使其转入休眠状态。

可以在调度器启动前调用 `xTimerStart()`，但此时软件定时器要等到调度器真正启动后才开始计时。

> *注意：切勿从中断服务程序中调用 `xTimerStart()`，应改用其中断安全版本 `xTimerStartFromISR()`。*

<a name="list6.4" title="代码清单 6.4 xTimerStart() API 函数原型"></a>

```c
BaseType_t xTimerStart( TimerHandle_t xTimer, TickType_t xTicksToWait );
```
***代码清单 6.4*** *`xTimerStart()` API 函数原型*

**xTimerStart() 参数和返回值**

- `xTimer`

  要启动或复位的软件定时器句柄。该句柄由创建软件定时器时调用的 `xTimerCreate()` 返回。

- `xTicksToWait`

  `xTimerStart()` 通过定时器命令队列把“启动定时器”命令发送到守护任务。队列已满时，`xTicksToWait` 指定调用任务为等待队列出现可用空间而保持阻塞状态的最长时间。

  如果 `xTicksToWait` 为 0 且定时器命令队列已满，`xTimerStart()` 将立即返回。

  阻塞时间以 Tick 周期为单位，因此对应的绝对时间取决于 Tick 频率。宏 `pdMS_TO_TICKS()` 可将毫秒转换为 Tick 数。

  如果在 `FreeRTOSConfig.h` 中将 `INCLUDE_vTaskSuspend` 设为 1，那么把 `xTicksToWait` 设为 `portMAX_DELAY` 可使调用任务无限期地保持阻塞状态，等待定时器命令队列出现可用空间。

  如果在调度器启动前调用 `xTimerStart()`，则忽略 `xTicksToWait`，函数行为与该参数设为 0 时相同。

- 返回值

  有两个可能的返回值：

  - `pdPASS`

    仅当“启动定时器”命令成功发送到定时器命令队列时，才返回 `pdPASS`。

    如果守护任务的优先级高于调用 `xTimerStart()` 的任务，那么启动命令会在 `xTimerStart()` 返回前得到处理。这是因为定时器命令队列一有数据，守护任务就会抢占调用任务。

    如果指定了非零阻塞时间，调用任务可能先进入阻塞状态等待队列出现可用空间，但命令在阻塞时间到期前已成功写入定时器命令队列。

  - `pdFAIL`

    如果队列已满，无法写入“启动定时器”命令，则返回 `pdFAIL`。

    如果指定了非零阻塞时间，调用任务会进入阻塞状态，等待守护任务在定时器命令队列中腾出空间，但在空间出现之前阻塞时间已经到期。

```c
#define mainONE_SHOT_TIMER_PERIOD pdMS_TO_TICKS( 3333 )
#define mainAUTO_RELOAD_TIMER_PERIOD pdMS_TO_TICKS( 500 )

int main( void )
{
    TimerHandle_t xAutoReloadTimer, xOneShotTimer;
    BaseType_t xTimer1Started, xTimer2Started;

    /* 创建单次定时器，并将新定时器的句柄保存到 xOneShotTimer。 */
    xOneShotTimer = xTimerCreate(
        /* 软件定时器的文本名称，FreeRTOS 不会使用该名称。 */
                                  "OneShot", 
        /* 软件定时器的周期，单位为 Tick。 */
                                   mainONE_SHOT_TIMER_PERIOD, 
        /* 将 xAutoReload 设为 pdFALSE 可创建单次软件定时器。 */
                                   pdFALSE,
        /* 本例不使用定时器 ID。 */
                                   0,
        /* 新软件定时器使用的回调函数。 */
                                   prvOneShotTimerCallback );

    /* 创建自动重载定时器，并将新定时器的句柄保存到 xAutoReloadTimer。 */
    xAutoReloadTimer = xTimerCreate(
        /* 软件定时器的文本名称，FreeRTOS 不会使用该名称。 */
                                     "AutoReload",
        /* 软件定时器的周期，单位为 Tick。 */
                                     mainAUTO_RELOAD_TIMER_PERIOD,
        /* 将 xAutoReload 设为 pdTRUE 可创建自动重载定时器。 */
                                     pdTRUE,
        /* 本例不使用定时器 ID。 */
                                     0,
        /* 新软件定时器使用的回调函数。 */
                                     prvAutoReloadTimerCallback );

    /* 检查两个软件定时器是否创建成功。 */
    if( ( xOneShotTimer != NULL ) && ( xAutoReloadTimer != NULL ) )
    {
        /* 启动软件定时器，并将阻塞时间设为 0（不阻塞）。调度器尚未启动，
           因此这里指定的任何阻塞时间原本也会被忽略。 */
        xTimer1Started = xTimerStart( xOneShotTimer, 0 );
        xTimer2Started = xTimerStart( xAutoReloadTimer, 0 );

        /* xTimerStart() 通过定时器命令队列实现，因此当队列已满时调用会
           失败。调度器启动后才会创建定时器服务任务，所以发送到命令
           队列的所有命令都要等调度器启动后才能得到处理。检查两次
           xTimerStart() 调用是否都成功。 */
        if( ( xTimer1Started == pdPASS ) && ( xTimer2Started == pdPASS ) )
        {
            /* 启动调度器。 */
            vTaskStartScheduler();
        }
    }

    /* 与以往示例一样，程序不应执行到这里。 */
    for( ;; );
}
```

## 6.6 定时器 ID

每个软件定时器都有一个 ID。它是一个标签值，应用程序开发者可以按任意用途使用。ID 保存在 `void` 指针（`void *`）中，因此既可以直接保存整数值，也可以指向其他对象，或作为函数指针使用。

创建软件定时器时会为其设置初始 ID 值。之后可以使用 `vTimerSetTimerID()` API 函数更新 ID，并使用 `pvTimerGetTimerID()` API 函数查询 ID。

与其他软件定时器 API 函数不同，`vTimerSetTimerID()` 和 `pvTimerGetTimerID()` 会直接访问软件定时器，不会向定时器命令队列发送命令。

任一定时器到期时都会执行 `prvTimerCallback()`。该函数通过传入的参数判断本次调用是由单次定时器到期，还是由自动重载定时器到期所触发。

`prvTimerCallback()` 还演示了如何使用软件定时器 ID 保存定时器专属数据。每个软件定时器都在自己的 ID 中记录到期次数，自动重载定时器则利用该计数在第五次执行后停止自身。

`prvTimerCallback()` 的实现见代码清单 6.11。

<a name="list6.11" title="代码清单 6.11 示例 6.2 使用的定时器回调函数"></a>

```c
static void prvTimerCallback( TimerHandle_t xTimer )
{
    TickType_t xTimeNow;
    uint32_t ulExecutionCount;

    /* 软件定时器的到期次数保存在定时器 ID 中。读取 ID，将其递增，再把
       结果保存为新的 ID 值。ID 是 void 指针，因此要强制转换为 uint32_t。 */
    ulExecutionCount = ( uint32_t ) pvTimerGetTimerID( xTimer );
    ulExecutionCount++;
    vTimerSetTimerID( xTimer, ( void * ) ulExecutionCount );

    /* 获取当前 Tick 计数。 */
    xTimeNow = xTaskGetTickCount();

    /* 创建单次定时器时，其句柄已保存到 xOneShotTimer。将传入本函数的
       句柄与 xOneShotTimer 比较，以判断到期的是单次定时器还是自动重载
       定时器，然后输出字符串显示回调函数的执行时刻。 */
    if( xTimer == xOneShotTimer )
    {
        vPrintStringAndNumber( "One-shot timer callback executing", xTimeNow );
    }
    else
    {
        /* xTimer 不等于 xOneShotTimer，因此到期的必定是自动重载定时器。 */
        vPrintStringAndNumber( "Auto-reload timer callback executing", xTimeNow);

        if( ulExecutionCount == 5 )
        {
            /* 自动重载定时器执行 5 次后将其停止。本回调函数在 RTOS 守护
               任务的上下文中执行，因此不得调用可能使守护任务进入阻塞
               状态的函数。为此将阻塞时间设为 0。 */
            xTimerStop( xTimer, 0 );
        }
    }
}
```

## 6.7 更改定时器的周期

每个官方 FreeRTOS 移植版本都附带一个或多个示例项目。大多数示例项目都具有自检功能，并通过 LED 直观显示项目状态：如果自检始终通过，LED 会缓慢翻转；一旦自检失败，LED 就会快速翻转。

一些示例项目在任务中执行自检，并使用 `vTaskDelay()` 控制 LED 翻转速率；另一些示例项目在软件定时器回调函数中执行自检，并通过定时器周期控制 LED 翻转速率。

<a id="671-the-xtimerchangeperiod-api-function"></a>
### 6.7.1 xTimerChangePeriod() API 函数

`xTimerChangePeriod()` 函数用于更改软件定时器的周期。

如果使用 `xTimerChangePeriod()` 更改正在运行的定时器周期，定时器会使用新周期重新计算到期时间。新的到期时间以调用 `xTimerChangePeriod()` 的时刻为基准，而不是以定时器最初启动的时刻为基准。

如果使用 `xTimerChangePeriod()` 更改处于休眠状态（未运行）的定时器周期，定时器会计算新的到期时间并转入运行状态，也就是开始运行。

> *注意：切勿从中断服务程序中调用 `xTimerChangePeriod()`，应改用其中断安全版本 `xTimerChangePeriodFromISR()`。*

<a name="list6.12" title="代码清单 6.12 xTimerChangePeriod() API 函数原型"></a>

```c
BaseType_t xTimerChangePeriod( TimerHandle_t xTimer,
                               TickType_t xNewPeriod,
                               TickType_t xTicksToWait );
```
***代码清单 6.12*** *`xTimerChangePeriod()` API 函数原型*

**xTimerChangePeriod() 参数和返回值**

- `xTimer`

  要更新周期的软件定时器句柄。该句柄由创建软件定时器时调用的 `xTimerCreate()` 返回。

- `xNewPeriod`

  软件定时器的新周期，单位为 Tick。宏 `pdMS_TO_TICKS()` 可将毫秒转换为 Tick 数。

- `xTicksToWait`

  `xTimerChangePeriod()` 通过定时器命令队列把“更改周期”命令发送到守护任务。队列已满时，`xTicksToWait` 指定调用任务为等待队列出现可用空间而保持阻塞状态的最长时间。

  如果 `xTicksToWait` 为 0 且定时器命令队列已满，`xTimerChangePeriod()` 将立即返回。

  阻塞时间以 Tick 周期为单位，宏 `pdMS_TO_TICKS()` 可将毫秒转换为 Tick 数。

  如果在 `FreeRTOSConfig.h` 中将 `INCLUDE_vTaskSuspend` 设为 1，那么把 `xTicksToWait` 设为 `portMAX_DELAY` 可使调用任务无限期地保持阻塞状态，等待定时器命令队列出现可用空间。

  如果在调度器启动前调用 `xTimerChangePeriod()`，则忽略 `xTicksToWait`，函数行为与该参数设为 0 时相同。

- 返回值

  有两个可能的返回值：

  - `pdPASS`

    仅当“更改周期”命令成功发送到定时器命令队列时，才返回 `pdPASS`。

    如果指定了非零阻塞时间，调用任务可能先进入阻塞状态等待队列出现可用空间，但命令在阻塞时间到期前已成功写入定时器命令队列。

  - `pdFAIL`

    如果队列已满，无法写入“更改周期”命令，则返回 `pdFAIL`。

    如果指定了非零阻塞时间，调用任务会进入阻塞状态，等待守护任务在队列中腾出空间，但在空间出现之前阻塞时间已经到期。

代码清单 6.13 展示了一个在软件定时器回调函数中执行自检的 FreeRTOS 示例。自检失败后，示例使用 `xTimerChangePeriod()` 提高 LED 的翻转速率。执行自检的软件定时器称为“检查定时器”。

<a name="list6.13" title="代码清单 6.13 使用 xTimerChangePeriod()"></a>

```c
/* 检查定时器的初始周期为 3000 毫秒，因此 LED 每 3 秒翻转一次。如果
   自检功能发现异常状态，检查定时器的周期将缩短为 200 毫秒，使 LED
   以快得多的速率翻转。 */
const TickType_t xHealthyTimerPeriod = pdMS_TO_TICKS( 3000 );
const TickType_t xErrorTimerPeriod = pdMS_TO_TICKS( 200 );

/* 检查定时器使用的回调函数。 */
static void prvCheckTimerCallbackFunction( TimerHandle_t xTimer )
{
    static BaseType_t xErrorDetected = pdFALSE;

    if( xErrorDetected == pdFALSE )
    {
        /* 尚未检测到错误，再次运行自检函数。该函数要求示例创建的每个
           任务报告自身状态，同时检查所有任务是否仍在运行（从而能够
           正确报告状态）。 */
        if( CheckTasksAreRunningWithoutError() == pdFAIL )
        {
            /* 一个或多个任务报告了异常状态，可能已经发生错误。缩短检查
               定时器的周期，提高本回调函数的执行频率，从而提高 LED 的
               翻转速率。本回调函数在 RTOS 守护任务的上下文中执行，因此
               阻塞时间设为 0，以确保守护任务绝不会进入阻塞状态。 */
            xTimerChangePeriod( 
                  xTimer,            /* 要更新的定时器。 */
                  xErrorTimerPeriod, /* 定时器的新周期。 */
                  0 );               /* 发送该命令时不阻塞。 */
        }

        /* 记录已经检测到错误。 */
        xErrorDetected = pdTRUE;
    }

    /* 翻转 LED。LED 的翻转速率取决于本函数的调用频率，而调用频率由检查
       定时器的周期决定。如果 CheckTasksAreRunningWithoutError() 曾返回
       pdFAIL，定时器周期就会从 3000 毫秒缩短为 200 毫秒。 */
    ToggleLED();
}
```

## 6.8 复位软件定时器

复位软件定时器就是重新启动定时器。复位后，到期时间将以定时器被复位的时刻为基准重新计算，而不再以最初启动的时刻为基准。图 6.9 展示了一个周期为 6 个 Tick 的定时器先被启动、随后复位两次，最终到期并执行回调函数的过程。

参照图 6.9：

- 定时器 1 在时刻 t1 启动。其周期为 6 个 Tick，因此回调函数最初计划在时刻 t7，也就是启动 6 个 Tick 后执行。

- 定时器 1 在时刻 t7 之前，也就是到期并执行回调函数之前被复位。它在时刻 t5 复位，因此回调函数的执行时刻被重新计算为 t11，即复位 6 个 Tick 后。

- 定时器 1 在时刻 t11 之前再次复位，同样发生在定时器到期并执行回调函数之前。它在时刻 t9 复位，因此回调函数的执行时刻再次被计算为 t15，即上次复位 6 个 Tick 后。

- 定时器 1 此后没有再次复位，因此会在时刻 t15 到期并执行回调函数。

本例模拟手机背光的行为。背光应当：

- 在用户按键时亮起。

- 如果用户在指定时间内继续按键，则保持亮起。

- 如果指定时间内没有按键操作，则自动关闭。

使用单次软件定时器来实现此行为：

- 用户按键时打开模拟背光，在软件定时器的回调函数中关闭背光。

- 每次按键时都复位软件定时器。

- 因此，要让背光保持开启，两次按键之间的时间不得超过软件定时器周期。如果定时器到期前没有新的按键操作将其复位，回调函数就会执行并关闭背光。

变量 `xSimulatedBacklightOn` 保存背光状态：设为 `pdTRUE` 表示背光开启，设为 `pdFALSE` 表示背光关闭。

软件定时器回调函数见代码清单 6.15。

<a name="list6.15" title="代码清单 6.15 示例 6.3 中单次定时器的回调函数"></a>

```c
static void prvBacklightTimerCallback( TimerHandle_t xTimer )
{
    TickType_t xTimeNow = xTaskGetTickCount();

    /* 背光定时器已到期，关闭背光。 */
    xSimulatedBacklightOn = pdFALSE;

    /* 打印关闭背光的时刻。 */
    vPrintStringAndNumber(
            "Timer expired, turning backlight OFF at time\t\t", xTimeNow );
}
```

示例 6.3 创建一个任务来轮询键盘[^11]。该任务见代码清单 6.16。不过，由于下一段说明的原因，这段代码并不是推荐的最佳设计。

[^11]: 向 Windows 控制台输出内容以及从控制台读取按键都会触发 Windows 系统调用。Windows 系统调用，包括访问控制台、磁盘或 TCP/IP 协议栈，可能对 FreeRTOS Windows 移植版本的行为产生不利影响，通常应当避免。

FreeRTOS 支持采用事件驱动方式设计应用程序。事件驱动设计只在事件发生时占用处理时间，不会把时间浪费在轮询尚未发生的事件上，因此效率很高。示例 6.3 无法采用事件驱动方式，因为在 FreeRTOS Windows 移植版本中处理键盘中断并不现实，所以只能使用效率较低的轮询方案。如果代码清单 6.16 展示的是中断服务程序，就应使用 `xTimerResetFromISR()` 代替 `xTimerReset()`。

<a name="list6.16" title="代码清单 6.16 示例 6.3 中用于复位软件定时器的任务"></a>

```c
static void vKeyHitTask( void *pvParameters )
{
    const TickType_t xShortDelay = pdMS_TO_TICKS( 50 );
    TickType_t xTimeNow;

    vPrintString( "Press a key to turn the backlight on.\r\n" );

    /* 理想情况下，应用程序应采用事件驱动设计，并通过中断处理按键操作。
       但 FreeRTOS Windows 移植版本不适合使用键盘中断，因此本任务通过
       轮询检测按键。 */
    for( ;; )
    {
        /* 是否有按键被按下？ */
        if( _kbhit() != 0 )
        {
            /* 检测到按键，记录当前时刻。 */
            xTimeNow = xTaskGetTickCount();

            if( xSimulatedBacklightOn == pdFALSE )
            {

                /* 背光原本处于关闭状态，将其打开并打印开启时刻。 */
                xSimulatedBacklightOn = pdTRUE;
                vPrintStringAndNumber(
                    "Key pressed, turning backlight ON at time\t\t", 
                    xTimeNow );
            }
            else
            {
                /* 背光已经开启，打印消息说明即将复位定时器以及复位时刻。 */
                vPrintStringAndNumber(
                    "Key pressed, resetting software timer at time\t\t", 
                    xTimeNow );
            }

            /* 复位软件定时器。如果背光原本关闭，此调用会启动定时器；如果
               背光原本开启，此调用会重新启动定时器。实际应用可能在中断
               中读取按键；如果本函数是中断服务程序，就必须使用
               xTimerResetFromISR() 代替 xTimerReset()。 */
            xTimerReset( xBacklightTimer, xShortDelay );

            /* 读取并丢弃按下的键，本简单示例不需要该按键值。 */
            ( void ) _getch();
        }
    }
}
```
